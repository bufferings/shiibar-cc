トレイアイコン表示仕様

メニューバーのトレイアイコンの見た目の正はこのファイル。ポップオーバーとウィンドウの見た目の正は window-design.html。挙動(状態モデル・通知・接続)の正は DESIGN.md §3 / §4.5。

デザイン原則

  • 色は赤ただひとつ = 「あなた宛の未読(unreviewed)」。通知の発火条件と 1:1。 status は色ではなく記号と濃度で表す — !(waiting・太)/ ✻ と 3 つの点(working)/ ✻ だけ(idle・全体 0.8)
  • Claude が居る窓: トレイ = フルハイトの角丸窓 + 左上スロットの 1 グリフ (Claude Code のスピナー文字)+ working のときだけ下段の 3 つの点。この組み合わせがロールアップを表す — 「ターミナルで Claude Code が動いている姿」をそのまま記号化したもの
  • 太さと形・濃度の階層が色の代役: ! は太く、working は 3 つの点が加わり、 idle・切断は全体の減光で沈む。グレースケールだけで優先順位が読める(色覚特性にも強い)
  • アイコンは操作ボタンを描かず、状態そのものを描く(▶/⏸ のようなメディアボタン文法は逆読みされるため不採用)

トレイ: 角丸の窓 + 左上スロットの 1 グリフ + working の 3 つの点(ロールアップ・常に 1 枠)

  • ロールアップ優先度: waiting > working > idle。トレイは全セッションの状態の代表 1 表示
  • テンプレートアイコン(モノクロ・メニューバーの文字色に自動追従)。暗い壁紙のバーでは白いグリフになる
  • 左上スロット(素の U+273B、x 6.4 基準)のグリフと、下段の 3 つの点の有無で状態を表す: idle・エージェントなしは ✻ だけ / working は ✻ の下に 3 つの点を並べる / waiting は ✻ と入れ替えで太い !(✻ の約 1.1 倍)。 どの状態も静止画で、アニメーションは使用しない(画像を変更するたびに一定の処理時間が必要なため。 DESIGN.md §8.51)。グリフと点だけなので、テンプレート画像のまま成立する
  • 赤バッジは窓の右肩にさせ、細い明色フチ(ハロー)を常時描く (明色バーでは実質不可視。テンプレート画像はバー色を知れないので条件分岐はしない)
  • 減光は 2 段階: idle = 全体 0.8 / エージェントなし = 0.45(値は実機調整。 idle と切断の見分けはこの濃度差のみ)。 daemon 切断中はトレイ全体をエージェントなしと同じ減光にする(古いロールアップを正常と誤認させない。DESIGN.md §4.5)

実装ノート

  • トレイは二層合成: 窓 + スロットグリフのテンプレート層(モノクロ・自動追従)の上に、 赤バッジを別レイヤーで重ねる。単一 NSImage に赤を描いてテンプレート指定すると赤が失われる点に注意。 スロットの ✻ と ! は文字グリフ(attributed string)、working の 3 つの点とバッジは自前描画
  • ✻ は素の Unicode 文字グリフ(U+273B TEARDROP-SPOKED ASTERISK 系の文字記号)のまま使い、 Anthropic ロゴのサンバースト形状には寄せない(ブランド流用回避。公開リポジトリなので特に)
  • 線の太さ・間隔・光学調整はすべて実機(Retina レンダリング)で最終決定。実機確認項目: ✻ と枠の間隔が融合して見えないか / ✻ の花弁が小サイズで潰れないか (潰れる場合は 9.5pt → 10.5pt まで戻してよい) / working の 3 つの点が小サイズで判別できるか / 赤バッジのハローが各種メニューバー色で機能するか
  • トレイのロールアップは「waiting 2 台」と「1 台」を区別しない(意図的な割り切り。内訳は、アイコンのクリックで開くポップオーバーの一覧が示す — window-design.html)
