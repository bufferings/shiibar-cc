ポップオーバーとウィンドウの表示仕様

ポップオーバーとウィンドウの見た目の正はこのファイル。挙動(開閉・幅による切り替え・ キー操作・一覧の区画・検索・会話ペイン・Resume / Branch / Jump)の正は DESIGN.md §4.5 / §4.6。 トレイアイコンの見た目は menubar-design.html。

ポップオーバーとウィンドウは同じ内容を表示し、レイアウトは 1 種類である。 実行中のセッションと過去の会話を 1 つの一覧に表示し、選択した会話の全文を会話ペインに表示する。 幅が狭いときは一覧のページと詳細ページを切り替え(1 列)、広いときは一覧と会話ペインを並べる(2 列)。

デザイン原則

  • 色: 赤 = 未確認(unreviewed)専用、黄 = スター専用。 青(アクセントカラー)は、選択・You のラベル・ピンの ON・主ボタン・ テキストボタンに使用する。 status(waiting / working / idle)には色を使用しない — 記号と濃度で表す(DESIGN.md §3.1 / §8.49)
  • レイアウトは 1 種類: ポップオーバー、細いウィンドウ、広いウィンドウは、 同じ構成要素(見出し行・一覧・会話ペイン・フッター)を表示する。幅によって変化するのは列の数だけである
  • 行のクリックは選択、実行は下部パネルのボタン: 行のクリックは、行を選択するだけである。 Jump / Resume / Branch は、選択中の行を対象にするラベル付きのボタン 1 組だけを下部パネルに表示し、 行の中には配置しない。下部パネルは一覧のページと詳細ページで同じ位置にあり、 Branch と主ボタンは、ページを切り替えても移動しない(View は一覧のページだけに表示する)。ボタン以外の実行の操作は、一覧にフォーカスがある間の ↩ と ⌘↩ と、 行のダブルクリック(↩ と同じく、選択した行の Jump / Resume を実行する)と、⌘ を押しながらのダブルクリック (⌘↩ と同じく、Branch を実行する)である。1 列で詳細ページを開くのは、下部パネルの View ボタンと 一覧にフォーカスがある間の → である。行の中には、詳細ページを開くボタンを配置しない (DESIGN.md §4.5「実行のボタン」「詳細ページを開く操作」「行のクリック」「行のダブルクリック」)
  • キーの割り当てを画面に表示する: 実行のキーと、詳細ページを開くキーは、下部パネルのボタンの中に表示する (Resume ↩ / Jump ↩ / Branch ⌘↩ / View →)。移動のキーは、キーの案内に表示する (1 列では下部パネルの左側、2 列では左の列のフッター)。同じキーを 2 か所に表示しない。 表示するキーはフォーカスの位置で変わる — 検索欄にフォーカスがある間は、キーの案内に ↩ List だけを表示し、 下部パネルのボタンを表示しない
  • 会話ペインは長い文章の閲覧を主目的として構成する: 主な内容は「自分の短い依頼 → Claude の長い発言」の繰り返しである。どの発言にも You / Claude のラベルを付け、 自分の発言には全幅の帯の地を付ける。Claude の発言は Markdown を描画した本文として扱う
  • 一覧と会話ペインは背景で区別する: 一覧は淡い地にカードを並べ、 会話ペインは通常のウィンドウ背景にする。選択する場所と閲覧する場所を背景で判別できる
  • History に残る実行中の会話は文字の印で示す: 1 行目(ラベル)の末尾に running。 状態記号(スピナー・!)は Running の区画の行だけが使用する — running の印は 最後に一覧を取得した時点の情報であり、現在の status を示さない
  • アイコンは線画の SVG(絵文字を使用しない)。状態記号の凡例は UI に配置しない (吹き出し ! / 瞬くスピナー / 薄い ✻ は形で判別できる)

見出し行

  • ポップオーバーとウィンドウの上端は見出し行 1 行である。ポップオーバーは左から 検索欄 / ⟳ / Open in window / ⌄、ウィンドウは 検索欄 / ⟳ / ピン / ⌄ を並べる (ウィンドウでは Open in window の位置がピンに替わる)。ウィンドウはタイトルバーを表示せず、 見出し行の左端に信号機ボタンを配置する(挙動は DESIGN.md §4.5「見出し行」)
  • 検索欄のプレースホルダは Search (2+ characters)。先頭に虫眼鏡のアイコン(13px・二次色)
  • 検索欄の形: 高さ 24px(見出し行のボタンと同じ高さで、上下の中心が揃う)・角丸 6px・ カードの色の地 + 1px の枠・左右の余白 8px・アイコンと文字の間隔 6px・文字 12px。 地とアイコンはアプリが描画し、その中に枠なしの入力欄を配置する(DESIGN.md §4.6「検索欄」)。 フォーカスリング・最近の検索のメニューは表示しない。文字がある間だけ、右端に消去のボタン (12px の塗りつぶした円に ×)を表示する(DESIGN.md §4.6「検索欄」)。 地のどこをクリックしても、入力欄にフォーカスが移る
  • ⟳(ツールチップ Refresh (⌘R)): Refresh を実行する(DESIGN.md §4.6)。静止時は背景なし。ホバーでグレーの背景を表示し、 押下で一段濃くする。実行中は矢印グリフが回転する(回転の規律は DESIGN.md §4.6 / §9。 working のグリフ循環スピナー ✻ とは別の文法)
  • Open in window(ツールチップ Open in window): ウィンドウの枠のアイコン。 背景の表示は ⟳ と同じ
  • ピン(ツールチップ Keep on top): 斜めに傾いた画びょう(16 の格子・線の太さ 1.2)。 OFF = 輪郭だけ・二次色 / ON = アクセントカラーの塗り + ボタンの背景(アクセントカラーの 16%。押している間は 24%。ホバーでは変更しない) (DESIGN.md §4.5「ピン」)
  • ⌄: 常に表示するチップ(正方形 24×24・角丸 7px)を背景に持つ。 前景色ベースで 通常 10% / ホバー 16% / プレス 24%。グリフの色は変更しない。 メニューの内容(ネイティブメニュー項目)は OS 標準のハイライトのまま

一覧のページ(1 列): Running と History

  • 区画は上が Running、下が History。見出しは 太字の区画名 + 行数(行数は二次色)。検索中の行数は、表示している行の数である。 History の行が上限を超えている間は、行数の位置に first 100 を表示する(DESIGN.md §4.6「History の区画」)。 行が 1 つも無い区画は見出しごと表示しない(DESIGN.md §4.5「一覧は 2 つの区画」)
  • 行は 1 枚ずつのカード(角丸 10px・1px の枠・カード間 6px)。構成は両区画で共通: 左に 3 行の文字 / 右に記号と時間の列(幅 28px)。文字は、カードの左の余白から始まる。 3 行は、上から、ラベル(二次色 11px)/ タイトル(13px・太字)/ 最後の発話(二次色 11px)である。 タイトルは、どの行も太字で表示する。ラベルとタイトルの間隔は 1px、タイトルと最後の発話の間隔は 4px で、 ラベルとタイトルを 1 組にして、最後の発話と区別する(間隔は DESIGN.md §9)。 記号と時間の列は、上に記号(状態記号は 20px、スターは 16px。20px の枠の上端は 1 行目 = ラベルの位置)、下に経過時間(ラベルと同じ二次色 11px。 3 行目 = 最後の発話の位置)を、列の中央にそろえて表示する。3 行の文字は、どの行も列の手前で終わり、末尾を省略する(ellipsis)。 経過時間は省略しない(列の幅に収まらない場合は、その行の列を広げる)。 行の中にボタンは無い(スターを除く)(DESIGN.md §4.5「一覧は 2 つの区画」)
  • Running の行: 列の上 = 状態記号。1 行目 = ラベル、 2 行目 = タイトル(waiting の間は許可内容)、3 行目 = 最後に自分が送った発話 (内容の規則は DESIGN.md §4.5「Running の行」)。選択中は、下部パネルの主ボタンが Jump になる
  • History の行: 列の上 = スター。1 行目 = フォルダラベル、 2 行目 = タイトル、3 行目 = 最後に自分が送った発話。 選択中は、下部パネルの主ボタンが Resume になる。スター付きの行が先に並ぶ(DESIGN.md §4.6「History の区画」)
  • History に残る実行中の会話: 1 行目(ラベル)の末尾に · running。 選択中は、下部パネルの主ボタンが disabled の Jump(ツールチップ Running in a terminal Shiibar CC can't drive)になり、Branch は通常の表示
  • 未確認(unreviewed)= 状態記号の右肩の赤バッジ(明色ハロー付き。 トレイアイコンの「窓の右肩のバッジ」と同じ文法 — menubar-design.html)。タイトルの太さでは未確認を示さない。 行の右端には未確認の印を配置しない
  • クリック: スター以外の部分をクリックすると、その行を選択する。 青で表示している選択中の行をクリックすると、選択を解除する(選択なしになる)。 灰色で表示している選択中の行をクリックしたときは、選択を解除せず、一覧にフォーカスを移す (ウィンドウが key でなかった場合は、key にする)。クリックでは詳細ページを開かない。 行のクリックは、一覧にフォーカスを移す(検索欄のカーソルは消える。 DESIGN.md §4.5「行のクリック」「キー操作」)
  • ダブルクリック: スター以外の部分をダブルクリックすると、 その行を選択し、一覧にフォーカスを移して、Jump(Running の行)または Resume(History の行)を実行する。 ⌘ を押しながらダブルクリックすると、Jump / Resume の代わりに Branch を実行する (⌘ を押しているかどうかは、2 回目のクリックの時点で判定する)。 対応するボタンが disabled のときは、選択とフォーカスの移動だけを行う。行の状態(未選択・青・灰色)による違いは無い。 ダブルクリックでは選択を解除しない。そのため、青で表示している選択中の行のクリックによる選択の解除は、 マウスのボタンを押してからシステムのダブルクリックの間隔が経過した時点で実行する。 3 回以上の連続したクリックは、Jump / Resume を再実行しない(DESIGN.md §4.5「行のダブルクリック」)
  • ホバーと選択: ホバー中のカードは枠だけを淡い青にする。 選択中のカードは、キーの操作対象が一覧である間(ポップオーバーまたはウィンドウが key で、かつ一覧に フォーカスがある間)は淡い青の地 + 淡い青の枠、検索欄にフォーカスがある間と、 ウィンドウが key でない間(他のアプリを操作している間など)は淡い灰色の地 + 灰色の枠にする (キーの操作対象が一覧かどうかを、色で区別する。DESIGN.md §4.5「行の選択」)。選択中のカードは、ホバーしても枠の色を変更しない。文字・経過時間・状態記号・スターの色は、 選択中も変更しない。選択している行は 0 行または 1 行で、 利用者が行を選択するまでは、どの行も選択していない(DESIGN.md §4.5「行の選択」)。押せない部分(区画の見出し・フッター)にはホバーの表示を付けない
  • 固定フッター(スクロールに含めない): 上から警告行、メッセージ行、下部パネル。 下部パネルは詳細ページと同じもので、左側にキーの案内、右側に選択中の行の View、Branch、主ボタンを配置する (View は一覧のページだけに表示する)。 行を選択していない間は、キーの案内だけを表示する(パネルの高さは変わらない)。 下部パネルの上端は 1px の区切り線(下記「固定フッター」「下部パネルの状態」)
  • UI 文言は英語。行の内容(依頼文・許可内容・タイトル)は利用者のデータをそのまま表示する

行の構成要素: 記号と時間の列・状態記号・スター

  • 記号と時間の列(カードの右端。幅 28px): 上に記号、下に経過時間(二次色 11px)を、 列の中央にそろえて表示する。記号は、Running の行が状態記号(20px)、History の行がスター(16px)である。 どちらも同じ位置の 20px の枠に表示し、スターの中心は枠の中心にそろえる。 枠の上端は 1 行目(ラベル)の位置に、経過時間は 3 行目(最後の発話)の位置にそろえる。 カードの左端には、記号のための場所は無い(DESIGN.md §4.5「一覧は 2 つの区画」/ §9)
  • 状態記号(記号と時間の列の上・20px 相当。Running の行): 薄い ✻(静止・50% 濃度)= idle(U+273B の文字グリフ。Claude Code の TUI が 処理を終えたときに表示する「✻ Worked for Ns」のマーカーと同じ「静止している Claude」)/ グリフ循環スピナー(100% 濃度)= working (Claude Code の TUI と同じ · ✢ ✳ ✶ ✻ ✽ の循環。位置 = round((1−cos(2πt/2000))/2 × 5) — 周期 2 秒のコサインイージングで、両端に留まり中間を速く通過する。等間隔のステップにしない。 動作させる条件は DESIGN.md §4.5「表示中の更新」)/ 輪郭だけの吹き出し + 太い ! = waiting(塗りなし — Claude が利用者に話しかけて返事を待っている)。 モックは静止画のため、working は循環の 1 コマ(✻)を示す(idle との差は濃度のみ)
  • 赤バッジ: 状態記号の右肩に表示する塗りの円 + 細い明色のフチ(ハロー)。 状態記号の種類によらず同じ位置
  • スター(記号と時間の列の上・16px。状態記号より小さい。History の行): 状態記号と同じ位置の 20px の枠の中心に表示する。クリックに反応する範囲は、20px の枠である。 線の太さは、輪郭だけの星が 1.1px、塗りの星が 0.7px である。3 状態 — なし(記号の位置は空)/ 行のホバー中 = 輪郭だけの星(二次色)/ スター付き = 黄色の塗りの星(塗り #f5b400・輪郭 #d39700。 ホバーしていなくても表示する)。スターのクリックでは行を選択しない。挙動は DESIGN.md §4.6「スター」

固定フッター: 警告行・メッセージ行・キーの案内

  • 警告行(表示する条件は DESIGN.md §4.5「異常の可視化」): モノクロ(二次色)+ ⚠ 記号・12px。赤は使用しない(赤 = 未確認専用)。 クリックの動作は無い
  • メッセージ行(二次色 11px・クリック不可): 表示する内容があるときだけ、 キーの案内の上に 1 行で表示する(内容と優先順位は DESIGN.md §4.6「メッセージ行」)。
    • Refresh(⟳ / ⌘R): 実行中 Refreshing… / 正常終了後 ✓ Refresh done / reconcile の失敗(TCC 以外)Refresh failed。件数は表示しない。TCC エラーは警告行で表示する (結果の組み合わせは DESIGN.md §4.6「検索欄」の表)
    • 全構築中: Indexing 340 of 4,200…。全構築中は検索欄を無効の表示にする。 History は完了後に一度に表示する(徐々に行が増える表示にしない)。Running の区画は構築を待たずに 表示する。回転する ✻ は使用しない — グリフ循環スピナーは working を意味する
  • キーの案内(二次色 11px・常に表示する): キーの表記はモノスペースの小さなチップ、 その右に動作の名前。1 列では下部パネルの左側(一覧のページと詳細ページの両方)、 2 列では左の列のフッターに表示する。キーの案内は移動のキーだけを示す (実行のキーと、詳細ページを開く → は、下部パネルのボタンの中に表示する)。表示する組み合わせは、フォーカスの位置で次のとおりに変わる (DESIGN.md §4.5「固定フッター」):
    • 検索欄にフォーカスがある間(1 列・2 列とも): ↩ List だけ
    • 一覧にフォーカスがある間の 1 列の一覧のページ(下部パネルの左側): ↑↓ Move
    • 一覧にフォーカスがある間の 2 列(左の列のフッター): ↑↓ Move
    • 1 列の詳細ページ(下部パネルの左側): ⌥↑↓ Prev / Next / ← Back (詳細ページを表示している間は、検索欄にフォーカスが移動しないので、フォーカスは常に一覧にある。下記「キー操作」)
  • 表示していない会話の数: History の行が上限(DESIGN.md §9)を超えたときは、 最後のカードの下に 1 行(二次色 12px・中央寄せ)— 242 more — search to narrow down (検索中は 242 more — refine your search)。カードにはしない。 この間、区画の見出しは History first 100 である(first 100 は、行数と同じ二次色)
  • 空状態: Running と History の両方に行が無いときだけ、一覧の位置に 1 行 (二次色 12px)— 空クエリは No conversations、検索中は No matching conversations(DESIGN.md §4.6「空状態」)

詳細ページ(1 列): 選択した会話の会話ペイン

  • 1 列では、一覧のページの下部パネルの View ボタン、または一覧にフォーカスがある間の → で、選択中の行の詳細ページを右からスライドして表示する。 戻るボタン、または一覧にフォーカスがある間の ← で、一覧のページに戻る(DESIGN.md §4.5「幅による切り替え」「キー操作」。時間は §9)
  • ヘッダ: 左から 戻るボタン(チップ)/ フォルダとタイトル (1 行目 = フォルダラベル · 経過時間・二次色 11px、2 行目 = タイトル・13.5px・セミボールド。フォルダラベルは、一覧のカードのラベルと同じ文字で、running の印は表示しない。DESIGN.md §4.6)/ 一覧の中での位置(2 / 4・二次色 11px)/ 前後の会話へ移動するボタン(上向きと下向きのセグメンテッドコントロール。⌥↑ / ⌥↓ と同じ)。 ヘッダ下の区切り線は常に表示する(DESIGN.md §4.6「会話ペインの表示」)
  • 検索バー行(会話内にヒットがあるときだけ): 左端に 検索文字列の文 Matches for “tag”(Matches for は二次色、引用符で囲んだ検索文字列は通常の色。 長い検索文字列は途中を省略する。表示だけで変更できないので、地・枠・虫眼鏡のアイコンを付けない)、 右端にカウンタ N of M と ‹ › のセグメンテッドコントロール (ツールチップ Previous match / Next match)
  • その下がメッセージ面。古い順に並び、下端が最新である。右端はミニマップ、 最後のメッセージの下に終端マーカー。↑ / ↓ は会話をスクロールする(Space と Page Up / Page Down も同じ)。 前後の会話への切り替えは ⌥↑ / ⌥↓ である(DESIGN.md §4.5「キー操作」)
  • 下部パネルは常に表示する。左側にキーの案内、右端が主ボタン(Resume または Jump)、 その左が Branch(下記「下部パネルの状態」)。View は表示しない。Branch と主ボタンの位置と大きさは 一覧のページの下部パネルと同じで、ページを切り替えても移動しない。警告行とメッセージ行は、下部パネルのすぐ上に表示する
  • 詳細ページに見出し行は無い。検索欄・⟳・ピン・⌄ は、一覧のページに戻って操作する
  • ウィンドウが 1 列の幅のときも同じ表示で、ヘッダの左端に信号機ボタンを配置する

2 列(文字の大きさ 13 のとき、ウィンドウの幅が 780pt 以上)

  • ウィンドウの幅を変更して 1 列と 2 列が切り替わっても、キーの操作対象は変化しない。 一覧にフォーカスがある状態で切り替わった場合は、選択中のカードは青のままで、下部パネルのボタンも表示したままである。 検索欄にフォーカスがある状態で切り替わった場合は、検索欄にフォーカスを保持する (DESIGN.md §4.5「幅による切り替え」の「幅を変更したとき」)

  • 下部パネルの左側には何も配置しない(キーの案内は左の列のフッターにある)。View は表示しない (選択中の会話は右の列に表示している)

  • 選択中の行に session_id が無いときは、ヘッダと下部パネルを通常どおり表示し、 メッセージ面の中央に No conversation to show(二次色 12px)だけを表示する (1 列の詳細ページも同じ)

下部パネルの状態

  • 挙動の正は DESIGN.md §4.6「下部パネル」・「Jump」。ここでは形だけを示す: 右端 = 主ボタン(Resume または Jump)、その左 = Branch(副ボタン・枠線のみ)。対象は選択中の行である。 1 列の一覧のページでは、Branch の左に View(副ボタン・Branch と同じ見た目)を表示する。 View は、選択中の行の詳細ページを開く(一覧にフォーカスがある間の → と同じ)。disabled の状態は無い。 1 列の詳細ページと 2 列の右の列には、View を表示しない(会話を表示しているため)。 パネルの高さは変化しない。Resume と Jump は同幅 (行を移動してボタンが替わっても、端の位置が移動しない)

  • 表示する場所は、1 列の一覧のページの下端・1 列の詳細ページの下端・2 列の右の列の下端である。 画面に表示する実行のボタンは常に 1 組で、Branch と主ボタンは、一覧のページと詳細ページで位置と大きさが同じ

メッセージ面の文法

  • 発言ごとにラベルの行: どの発言も、先頭に役割のラベル(11px・セミボールド)を表示する。 自分の発言は You(青)、Claude の発言は Claude(二次色)。1 つの依頼に Claude の発言が連続するときも、 すべての発言にラベルを付ける(発言の境目を示す)。ラベルは描画後テキストに含めない (ヒット計算・畳み境界・選択とコピーの対象外 — DESIGN.md §4.6)
  • 自分の発言 = 全幅の帯: 左端から右端までマージンなしで、ラベルと発言に帯の地を付ける。 発言は本文と同じウェイトで表示する。 太字にしない(帯が見出しの役割を持つので、文字を強調しない)。発言の文字は 13.5pt(文字の大きさ 13 のとき)。 帯の直前は広めの余白(節の切れ目)。スクロールすると、帯の並びから依頼の一覧を把握できる
  • Claude の発言 = Markdown を描画(描画範囲は DESIGN.md §4.6「会話ペインの表示」): コードブロックはモノスペース + 淡い背景 + 横スクロール。インラインコード・強調・見出し・ 箇条書きも描画する。地は付けない
  • パイプ表はグリッドで描画: ヘッダ行はセミボールド + 淡い背景、行間に罫線、 全列左揃え(列揃えの指定は無視)。セルの中のインライン(コード・強調)も描画する。 表は内容の幅のまま(本文の幅いっぱいに広げない)。セルは幅の上限(約 28em)で 折り返し、それでも収まらない表だけ、コードブロックと同じく表の中で横スクロール (DESIGN.md §8.38)。等幅フォントで整形する形は採用しない — 日本語のグリフ幅が モノスペースで揃わず、列が崩れる(DESIGN.md §8.37)
  • 発言ごとのコピー: 各発言のラベルの行の右端に、コピーのアイコンボタン (14px・二次色)を常に表示する。本文の文字と同じく、ミニマップの手前 8px より内側に配置する。 押した後は一定時間、アイコンをチェックマークに替える(同じ位置・同じ大きさ・同じ色。 表示時間は DESIGN.md §9、コピーする内容は §4.6「発言ごとのコピー」)
  • 選択とコピー(文法の正は DESIGN.md §4.6「選択とコピー」): 選択ハイライトは メッセージをまたいで連続する。ラベル・展開 / 畳みのボタン・コピーのボタンは 選択に含まれない。右クリックメニューは Copy(⌘C)/ Copy as Markdown(⇧⌘C)の 2 項目だけ
  • 本文の幅の上限: 本文の行長は約 60em を上限とする。ウィンドウを広げても行が 長くなりすぎない(コードブロックと、折り返しても収まらない表は、この上限の内側で横スクロール)
  • 本文の既定は 13pt・行間 1.7。コードブロックは 11.5pt(文字の大きさ 13 のとき)。 行間・段落間・ブロック間隔・帯の余白は本ページの CSS 値が実装の正(DESIGN.md §8.39)
  • ミニマップ = スクロールバー(右端・常時・幅 20pt): 会話全体の略図 (帯 = 濃い縞・本文 = 淡い塊・コード = 中間。文字は描かない)+ 半透明グレーのつまみ。 本文の文字はミニマップの手前 8px で折り返す(狭くなるのは文字の列だけ — 帯の背景は 右端まで、コードブロック・表の背景は元の列幅のまま)。 ドラッグでスクロール・ホバーで濃く・地のクリックでジャンプ。会話ペイン内に OS のスクロールバーは 表示しない(DESIGN.md §4.6「ヒットナビゲーション」/ §8.39)
  • 下端の手がかり: 最後のメッセージの下に終端マーカー Latest message · 3h ago(罫線ではさんだ淡い一行)。上に続きがある間だけ ヘッダ下に薄いスクロールシャドウ(最上部で消える)
  • メッセージ間のツール実行は何も描かない(DESIGN.md §4.6)
