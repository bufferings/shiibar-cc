## 背景

アプリの一覧(M44)は、過去の会話の行に「最後に自分が送った発話」を表示し、会話を分岐する
Branch を実行する。この 2 つに必要な CLI の機能を追加する。

## タスク

### T1: `resume --fork`

- `shiibar-cc resume` に `--fork` フラグを追加する(§4.4)。位置は他のオプションと同じく自由。
  `--fork` を指定すると、ターミナルで実行するコマンドの末尾に `--fork-session` を追加する
  (`cd '<cwd>' && claude --resume '<session-id>' --fork-session`)
- `open_resume_window` に `fork` の引数を追加する(§4.3)。iTerm2 と Terminal.app の両方で同じ扱いにする
- `--fork` 以外の動作(ウィンドウの開き方・cwd の確認・exit code)は変更しない
- usage の文字列と、`resume_cmd.rs` の先頭の doc コメントを更新する

### T2: search の `last_prompt`

- 索引に、会話ごとの「最後の人の発話」を保存する(§4.6「索引の内容」)。値は、発話列の最後の人の発話の
  先頭 1 行を trim して、先頭 80 文字に切り詰めたものである(タイトルのフォールバックと同じ切り詰め)。
  人の発話が無い会話は null
- スキーマを変更するので、`SCHEMA_VERSION` を上げる(既存の索引は、次の index または search で
  全再構築される — 既存の仕組みのまま)
- `conversations search --json` の各要素に `last_prompt` を追加する(§4.4。null 許容)。
  人間向けの表形式の出力は変更しない
- `conversations show` は変更しない

## テスト要求

- `--fork` の引数解析(あり / なし / 他のオプションとの順序)、コマンド文字列の生成(両ターミナル。
  `--fork-session` が末尾にあること、エスケープが既存どおりであること)
- `last_prompt` の抽出: 複数行の発話は先頭 1 行だけ / 80 文字を超える行の切り詰め / 人の発話が無い会話は null /
  最後の発話が対象になること(最初の発話ではない)/ 除外対象の発話(既存の発話列の抽出が除外するもの)は
  対象にしない
- search の JSON 契約テストに `last_prompt` を追加する。スキーマ不一致からの全再構築のテストが
  新しいバージョンでも成立すること
- 既存のテストを弱めない。実 osascript は起動しない。temp の状態ディレクトリを使用する。
  docs/ 以外に日本語を記述しない
