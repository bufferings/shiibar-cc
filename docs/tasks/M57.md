## 背景

`claude -p` で起動したセッションは、スクリプトや別のセッションが起動する実行である。この指示書の実装の前は、会話の一覧(History と検索)に表示され、
ターミナルで直接実行した場合は、実行中だけ Running にも表示される。別のセッションから起動された場合は、Running には表示されず、
プロセスが動作している間、History に `· running` の印で表示される。

この指示書は、`claude -p` のセッションを、hook、reconcile、会話の索引の 3 箇所で対象外にする。判別に使用する値は、`entrypoint` の `sdk-cli` だけである(§7-13)。

## タスク

### T1(proto・CLI): hook の report を drop する

- 仕様: DESIGN.md §4.1「target の生成規則」の先頭の項目
- 既存実装: `crates/shiibar-cc-proto/src/extract.rs`(`HookEnv`、`build_report`)、`crates/shiibar-cc/src/report_cmd.rs`
- 環境変数 `CLAUDE_CODE_ENTRYPOINT` の値が `sdk-cli` の場合は、祖先 walk を実行せず、何も送らずに exit 0 で終了する
  (どのイベントでも同じ。SessionEnd も送らない)。値の判定は、proto の純粋な関数に配置する(`HookEnv` には加えない。判定は、祖先 walk と
  `build_report` の前に実行するため)
- 変数が無い場合、空の場合、`sdk-cli` 以外の値の場合は、既存の処理に進む
- 判定は純粋な関数にして、環境変数の読み取りと分離する(テストは、実際の環境変数を変更しない)

### T2(client): reconcile が、対話でない方法で起動したセッションの pid を送らない

- 仕様: DESIGN.md §3.5 の手順 1
- 既存実装: `crates/shiibar-cc-client/src/reconcile.rs`(`gather`、`assemble_sessions`)、`crates/shiibar-cc/src/conversations/live.rs`(`~/.claude/sessions/<pid>.json` を読み取る既存の処理)
- `claude agents` の一覧の pid ごとに、`<sessions ディレクトリ>/<pid>.json` の `entrypoint` を読み取り、値が `sdk-cli` の pid を、セッションの一覧から除外する。
  ファイルが無い、読み取れない、JSON として解釈できない、`entrypoint` が無い、値が `sdk-cli` 以外の場合は、除外しない
- 除外は、ターミナルの走査と突き合わせる前に行う。除外した pid は、完全な回の判定(`complete`)に影響しない
- sessions ディレクトリの場所と、ファイルの読み取りは、注入できるようにする(テストは、実際の `~/.claude` を読み取らない)。
  `live.rs` の、sessions ディレクトリの解決の方法と一致させる

### T3(CLI): 索引が、対話でない方法で起動した会話の transcript を登録しない

- 仕様: DESIGN.md §4.6「索引の内容」・§4.4
- 既存実装: `crates/shiibar-cc/src/conversations/`(`transcript.rs`、`db.rs`、`mod.rs`。人の発話が無い transcript を登録しない処理と、`unregistered_files` の表)
- transcript の行のうち、`entrypoint` の項目を持つ行のすべてで、値が `sdk-cli` であるファイルは、会話として登録しない。
  `entrypoint` を持つ行が 1 つも無いファイルと、`sdk-cli` 以外の値を持つ行が 1 つでもあるファイルは、既存の規則(人の発話の有無)で判定する
- 登録しないファイルの扱いは、人の発話が無い transcript と同じにする(`(パス, mtime, サイズ)` を記録して、追いつきで読み直さない。
  登録済みの会話が、読み直しの結果、対象外になった場合は、索引から削除する。後から、`sdk-cli` 以外の値を持つ行が追加されたファイルは、次の追いつきで登録する)
- スキーマのバージョンを 1 つ上げる(更新の後の最初の実行で、索引を全構築する)
- `search` の結果と、`show`(exit 2)が、対象外の会話について、索引に無い session-id と同じ結果になること

## テスト要求

- T1: `CLAUDE_CODE_ENTRYPOINT` が `sdk-cli` の場合に、どのイベント(SessionStart、UserPromptSubmit、Stop、Notification、SessionEnd)でも、何も送らずに exit 0 になること。
  変数が無い場合、空の場合、`cli`、`claude-vscode`、未知の値の場合に、既存の動作が変化しないこと(既存のテストの期待値を変更しない)。
  CLI のテスト(`crates/shiibar-cc/tests/report_cli.rs`)に、`sdk-cli` の場合を加える(socket に何も書き込まれないこと)
- T2: `entrypoint` が `sdk-cli` の pid を除外すること。ファイルが無い、解釈できない、`entrypoint` が無い、`cli` の場合に、除外しないこと。
  除外しても、ほかのセッションの target の導出と、`complete` の値が変化しないこと
- T3: `entrypoint` を持つ行のすべてが `sdk-cli` の transcript を登録しないこと。`entrypoint` を持つ行が無い transcript、`cli` だけの transcript、
  `sdk-cli` と `cli` の両方の行を持つ transcript を登録すること。対象外のファイルを、追いつきで読み直さないこと。対象外のファイルに `cli` の行が追加された後に、登録すること。
  登録済みの会話が、スキーマの更新の後の全構築で、索引から無くなること。`search` と `show` の結果
- テストのデータは、架空の内容とパス(`/Users/example/...`)を使用する。実際の `~/.claude`、状態ディレクトリ、ネットワーク、AppleScript を使用しない
