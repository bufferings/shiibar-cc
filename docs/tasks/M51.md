## 背景

一覧は Running と History の 2 つの区画で、スター付きの会話は History の先頭に新しい順で表示している。スターは、
session_id の順序の無い集合として保存している。行は 1 枚ずつの枠(カード)で、区画の見出しは、区画名と行数の文字だけである。
区画は開閉できない。これらを、DESIGN.md の仕様に合わせて変更する。

## タスク

### T1: スターを順序付きの一覧として保存する

既存実装: `ShiibarCcCore` の `UnifiedListRows.swift`(`StarredSessions`)、`MainSurfaceConstants.swift`(`MainSurfaceDefaultsKeys`)、
`UnifiedListState.swift`(スターの切り替えと、一覧に無いスターの破棄)。`ShiibarCcApp` の `MainSurfaceModel.swift`(読み込みと保存)。

- スターを、session_id の順序付きの一覧として保持し、UserDefaults に保存する(§4.6「スター」)。
  保存には、順序の無い集合のキー(`cc.shiibar.starredSessionIDs`)とは別の、新しいキーを使用する
- スターを付けた会話は、一覧の末尾に追加する。スターの解除は、一覧から除く(残りの順序は変更しない)
- 一覧に無い session_id のスターを破棄する処理(クエリが空の一覧を取得した時点)は、残りのスターの順序を変更しない
- 順序の無い保存値の扱い(§4.6「スター」の「順序の無い保存値」): 新しいキーの値が無く、順序の無い集合のキーの値がある場合は、
  その集合をスターとして使用し、新しい順に表示する。クエリが空の一覧を取得した時点で、新しい順に並べた結果を、
  新しいキーに保存する。その前にスターを変更したときは、その時点で、取得済みの search の結果にある会話を新しい順に、
  結果に無い会話をその後に session_id の順に並べて、順序付きの一覧にしてから、変更を適用して保存する。
  新しいキーの値がある場合は、順序の無い集合のキーの値を使用しない(順序の無い集合のキーの値は削除しない)
- 新しいキーの値が文字列の配列でない場合は、値が無いものとして扱う(順序の無い集合のキーの値があれば、上記の扱いにする)。
  重複する session_id は、最初の 1 つだけを使用する

### T2: Starred と Recent の区画

既存実装: `ShiibarCcCore` の `UnifiedListRows.swift`(`UnifiedListSection`、行の識別子、`historyRows`、見出しの行数の文字列)、
`UnifiedListState.swift`(表示する行、History の上限、↑ / ↓ の移動、詳細ページの位置)、`UnifiedListKeys.swift`。
`ShiibarCcApp` の `UnifiedListView.swift`(区画の描画)。

- 区画を、上から Running、Starred、Recent の 3 つにする。Starred と Recent は、History の見出しの下に表示する(§4.5「一覧は 3 つの区画」)
- Starred は、search の結果のうち、スター付きの会話を、スターの一覧の順に表示する。Running の行と session_id が
  一致する会話は表示しない(§4.6「Starred の区画」)。表示する行の数に上限は無い
- Recent は、Running の行と一致する会話と、スター付きの会話を除いて、新しい順に表示する。上限(100 行)、
  `first 100` の見出し、`N more` の行は、Recent の行だけで数える(§4.6「Recent の区画」)
- 見出しを表示する条件(§4.5「一覧は 3 つの区画」の「表示しない見出し」): 行が 1 つも無い区画は、見出しごと表示しない(閉じている区画の行も、行として数える。閉じている区画は、見出しを表示する)。
  Starred と Recent のどちらにも行が無いときは、History の見出しも表示しない。Starred に行が無いときは、Recent の見出しも表示せず、
  History の見出しのすぐ下に Recent の行を表示する
- 見出しの行数(同じ節の「行数」): History の見出しは、Recent の見出しを兼ねている間だけ、Recent の見出しと同じ行数を表示する
  (`History 12`、`History first 100`)。それ以外の間は、行数を表示しない
- Starred の行の内容と動作は、Recent の行と同じである(3 行の内容、`· running` の印、下部パネルのボタン、cwd の無い会話の扱い、
  `session_id` での選択の保持)。Starred の行は、黄色の塗りの星を常に表示する(ツールチップは `Unstar`)
- スターの変更は、search を再実行せずに、直後に区画の振り分けへ反映する。Starred と Recent の間を移動した行の選択と、
  表示中のページを保持する(§4.5「行の選択」。スターの解除で、会話が Recent の上限を超える位置になった場合は、選択なしにする)
- ↑ / ↓ の移動、「一覧の先頭の行」、詳細ページの位置と前後の会話への切り替えは、Running、Starred、Recent の順に、
  表示している行を対象にする
- 検索中(§4.6「検索の適用範囲」): History の見出しの下に、Starred の行(スターの一覧の順)と、Recent の行(新しい順。上限まで)を、
  この順に、1 つの枠の中に続けて表示する。Starred と Recent の見出しは表示しない。`N more` の行は、この枠の下に表示する。
  History の見出しの行数は、表示している Starred の行と Recent の行の合計である(Recent の行が上限を超えている間は、
  `first` と、この合計の数)。スターを変更した行は、同じ枠の中で、変更の後の位置に移動する
- 空状態(`No conversations` / `No matching conversations`)は、どの区画にも行が無いときだけ表示する(閉じている区画の行も、行として数える)

### T3: 見出しと、行の枠

既存実装: `ShiibarCcApp` の `UnifiedListView.swift`(`SectionHeaderView`、行の描画)、`SurfaceStyle.swift`(`SurfaceScale` の見出しと行の寸法、色)。

- 見出しは 2 種類である(§4.5「一覧は 3 つの区画」。寸法と形は `docs/window-design.html`)。Running と History の見出しは、
  淡い灰色の地の帯である。Starred と Recent の見出しは、地の無い、文字だけの見出しである。
  どの見出しも、左から、Running の印(T4。Running だけ)、名前、行数、右端に山形を表示する。見出しの左右の端は、行の枠の左右の端にそろえる
- 検索中の Running と History の見出しは、文字だけの見出しにして、山形と Running の印を表示しない
- 区画の行を、1 つの枠の中に、区切り線で区切って並べる。枠は、角丸の枠線と地を持つ。行と行の間に隙間は無い。
  区切り線は、行の文字の左端から、枠の右端までの線である。行の内容(3 行の文字と、記号と時間の列)は変更しない
- 選択中の行は、行の全体の地の色で示す(キーの操作対象が一覧である間は淡い青、それ以外の間は淡い灰色。§4.5「行の選択」)。
  行ごとの枠は付けない。枠の最初の行と最後の行の地は、枠の角丸の内側に収める
- ホバーの表示は、行の地の色の変更にする(§4.5「行のクリック」)。見出しにホバーの表示は付けない
- `N more` の行は、Recent の行の枠の下(枠の外)に表示する
- 見出しの上下の余白と内側の上下、山形、Running の印、行の上下の余白は、文字の大きさに比率で連動させる(文字の大きさ 13 のときに、
  `window-design.html` の値になる)。左右の余白、見出しの中の要素の左右の間隔、角丸、枠線と区切り線の太さは固定である(§4.5「文字の大きさ」)
- 色は、システムの色に従う(固定の値を使用しない。ライトとダークの両方で、一覧の地、行の枠、区切り線、帯、選択中の行を判別できること)。
  Running の印の赤は、未確認の赤バッジと同じ色を使用する

### T4: 区画の開閉

既存実装: `ShiibarCcCore` の `UnifiedListState.swift`(入力の処理、選択)。`ShiibarCcApp` の `MainSurfaceModel.swift`
(UserDefaults の読み込みと保存)、`MainSurfaceController.swift`(マウスの入力の監視、key でないウィンドウのクリック)、`UnifiedListView.swift`。

- Running、Starred、Recent の区画と History を、見出しのクリックで開閉する(§4.5「区画の開閉」)。閉じている区画は、見出しだけを表示する
  (Recent の `N more` の行も表示しない)。アニメーションは無い。文字だけの見出しも、行の枠の左右の端までの幅の全体を、クリックの範囲にする
- History を閉じている間は、History の見出しだけを表示し、Starred と Recent の見出しと行を表示しない。
  History の開閉と、Starred と Recent の開閉は、別々に記憶する(History を開くと、Starred と Recent を、それぞれについて記憶している状態で表示する)
- History の見出しが Recent の見出しを兼ねている間(Starred に行が無い間): History の見出しは、History と Recent の両方が
  開いているときだけ、開いた状態で表示して、Recent の行を表示する。開いた状態の見出しのクリックは、History を閉じる。
  閉じた状態の見出しのクリックは、History と Recent の両方を開く
- 見出しのクリックから始まる、連続したクリックでは、最初の 1 回だけ開閉する(2 回目以降のクリックは、ポインタの下の要素(見出し、行、行の星)に関係なく、何もしない)。見出しのクリックは、キーのフォーカスと、ほかの区画の行の選択を変更しない。
  key でないウィンドウの見出しは、ウィンドウを key にして、同じクリックで開閉する
- 閉じているもの(Running、Starred、Recent、History)の集合を UserDefaults に記憶する(新しいキー)。ポップオーバーとウィンドウで共通にする。
  保存済みの値が想定の形でない場合と、この 4 つの名前でない値は、無視する(すべて開いた状態が既定)。
  表示していない見出しの状態も保持する
- 閉じている区画の行は、一覧に表示していない行として扱う(History を閉じている間は、Starred と Recent の両方を、閉じている区画として扱う):
  ↑ / ↓、「一覧の先頭の行」(検索欄の Enter、グローバルホットキー)、
  詳細ページの位置と前後の会話への切り替えの対象にしない。表示している行が 1 つも無いときは、行が 1 つも無いときと同じ扱いにする
- 選択中の行がある区画を閉じたときと、選択中の行が、閉じている区画に移動したときは、選択なしにする
  (1 列の詳細ページでは、一覧のページに戻る。§4.5「行の選択」)。選択中の Running の行が消えた後の、再取得を待つ規則は変更しない
  (再取得の結果で、行が、閉じている区画にある場合に、選択なしにする)
- 山形は、開いているときが下向き、閉じているときが右向きである。閉じている見出しは、名前を二次色にする。行数は、開いているときと同じ値を表示する(`first 100` を含む)
- Running の印: Running を閉じている間、waiting の行または未確認の行が 1 つ以上あるときに、名前の前に赤い点を表示する
- 検索中(検索文字列が有効になった時点から。search の結果を受け取る前と、エラー終了した場合を含む)は、記憶している状態に関係なく、
  Running、Starred、Recent、History のどれも、開いているものとして扱う(History の表示は T2)。見出しのクリックでは開閉しない
  (key でないウィンドウの見出しをクリックしたときは、ウィンドウを key にする)。
  記憶している状態は変更しない。検索を終えた時点で、選択中の行が、閉じている区画にある場合は、選択なしにする
- 開閉、検索中の扱い、選択への影響、Running の印の判定、表示する見出しと行数の判定は Core に実装する

### T5: 行のドラッグ

既存実装: `ShiibarCcCore` の `UnifiedListState.swift`(`PointerPress`、クリックとダブルクリックの判定)、`ListScroll.swift`。
`ShiibarCcApp` の `MainSurfaceController.swift`(マウスダウンの監視、キーの処理)、`MainSurfaceModel.swift`、`UnifiedListView.swift`。

- History の行(Starred と Recent の行)を、ドラッグで移動できるようにする(§4.5「行のドラッグ」)
- ドラッグできない行(同じ節の「ドラッグできない行」): Running の行、検索中のすべての行、Starred に行が無い間の Recent の行では、
  ドラッグを開始しない。これらの行の上(スターを除く)でボタンを押し、押した位置から 4pt 以上を移動した時点で、ポインタの近くに
  理由を 1 行で表示する。文言は、順に `Running is ordered automatically`、`Clear the search to reorder`、
  `Click the star to add it to Starred` である(複数に該当する行では、この順で、最初に該当した文言)。
  ダブルクリックの 2 回目以降の押下では、表示しない。2 秒後に消去する(§9)。次にマウスのボタンを押した時点でも消去する。
  1 回の押下で表示するのは 1 回で、表示した後は、ポインタに追従しない。この押下の、クリックとダブルクリックとしての動作は、変更しない。
  表示は、一覧のあるポップオーバーまたはウィンドウの中に収める(形は `window-design.html`)
- 開始: 行の上(スターを除く)でボタンを押し、押した位置から 4pt 以上を移動した時点(§9)。ダブルクリックの 2 回目以降の
  押下からは開始しない。ドラッグを開始した時点で、クリックと同じ選択とフォーカスの移動を実行する。key でないウィンドウの行を
  押した場合も、同じ押下で開始できる。ドラッグを開始した押下は、クリックとして扱わない(ボタンを離した時点でクリックと
  ダブルクリックの動作を実行しない)
- History の行で、青で表示している選択中の行を押した場合は、ボタンを押している間、選択の解除を実行しない。
  ダブルクリックの間隔が経過した時点でボタンを押したままのときは、ボタンを離した時点で解除する。ボタンを離す前にドラッグを
  開始したときは、解除しない。Running の行の動作は変更しない
- ドラッグ中の表示: 行の画像(角丸の枠と影を付ける。選択中の地の色は付けない。不透明度 0.92)が、押した位置との相対位置を保って、ポインタに追従する。
  元の行は、不透明度 0.35 で、その場に表示する。ほかの行は移動しない。カーソルは変更しない。
  挿入位置にならない行(Running と Recent の行。ドラッグ中の行を除く)は、不透明度 0.4 で表示する。Recent の `N more` の行は、薄くしない。
  ドラッグ中は、どの行にも、ホバーの表示(地の色の変更と、Recent の行の輪郭だけの星)を付けない
- 見出しの案内: Recent の行のドラッグ中は Starred の見出しに `Drop here to star` を、Starred の行のドラッグ中は Recent の見出しに
  `Drop here to unstar` を、山形の左に表示する(行数と同じ文字の大きさで、アクセントカラーである。ドラッグの開始から終了まで表示する。
  見出しを閉じている間も表示する)
- 移動先は、ポインタが一覧の表示範囲の中にある間、ポインタの上下の位置だけで判定する(一覧の中の左右の余白にある場合も、同じ高さにある要素の位置として扱う)。
  ポインタが一覧の表示範囲の外にある間は、移動先なしである。判定と表示は、§4.5「行のドラッグ」の表のとおりである(Starred の行の上半分と下半分、開いている見出し、
  閉じている見出し、Recent の区画、それ以外。要素の間の隙間と、一覧の端の扱いは、同じ節の「要素の間の隙間と、一覧の端」)。
  Starred の先頭への移動は、表示している最初の行の直前への移動である。線は、並びが変化しない位置でも表示する。
  行と行の間の線は、区切り線の位置に表示する。Recent の行のドラッグ中に、移動先を線で示している間は、Starred の行の枠も強調する。
  線、見出しの強調、枠の強調の形は、`window-design.html` のとおりである(線の太さ、輪の大きさ、強調の枠の太さは、文字の大きさに連動しない)
- ドラッグ中に、一覧の内容または配置が変化したときは、ポインタの位置から移動先を再計算する。
  **線を表示している間は、線の位置が、ドロップで配置する位置である**(一覧の内容が変化した直後も同じである。
  隙間で保持している移動先がある状態で、線の位置の前後に行が増減した場合を含む)
- ドロップ: Starred への移動は、スターの一覧の中で、移動する行を移動先の行の直前に配置する(末尾への移動は、一覧の末尾)。
  Recent の行の場合は、スターを付けて、同じ位置に配置する。移動する行以外の会話(Running にある会話を含む)の、
  相互の順序は変更しない。Recent への移動は、スターを解除する。表示している Starred の行の順序が変化しないドロップは、スターの一覧を変更しない(保存もしない)。
  移動した行の選択を保持する(移動先が閉じている区画のときは、選択なしにする)
- 取り消し(スターとその順序を変更しない。ドラッグの開始で実行した選択とフォーカスの移動は、元に戻さない): 移動先が無い状態でボタンを離したとき、Esc、
  ボタンを離したイベントを受信しないまま、ボタンが離れた状態が 0.25 秒続いたとき(離れた状態を検出した時点では取り消さない。離れた状態を検出している間は、自動スクロールしない)、
  ボタンを離したイベントを受信しないまま、次にボタンを押したとき、ポップオーバーまたはウィンドウを閉じたとき(アプリが非アクティブに
  なってポップオーバーを閉じる場合を含む)、ポップオーバーまたはウィンドウが key でなくなったとき、検索を開始したとき、ドラッグ中の行が、
  ドラッグを開始した区画の表示している行から無くなったとき(Recent の上限を超える位置への移動を含む)。
  ドラッグ中の Esc は、ドラッグの取り消しだけを実行する(ポップオーバーを閉じない)。ドラッグ中は、Esc 以外のキー(§4.5「キー操作」の表のキー)を処理しない
- 自動スクロール: ポインタが一覧の上端または下端から 40pt 以内(文字の大きさ 13 のとき。比率で連動する)にある間、
  その方向にスクロールする。速さは、端で 1200pt/秒、範囲の内側の端で 120pt/秒で、間は直線で変化する(速さは文字の大きさに連動しない。§9)。
  ポインタが一覧の上端より上、または下端より下にある間も、1200pt/秒でスクロールを続ける(左右の位置は条件にしない)。
  スクロールに合わせて、移動先を更新する
- **システムのドラッグ アンド ドロップ(`NSDraggingSession`、SwiftUI の `onDrag` / `onDrop` など)と、ペーストボードを使用しない**。
  マウスのイベントの追跡で実装する
