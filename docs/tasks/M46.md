## 背景

検索欄の文字を消去する操作は、キーでの削除だけである。マウスで消去できるように、消去のボタンを追加する。
ポップオーバーは、Settings の Appearance を Dark にしても、ライトで表示される。
ライトの一覧の地は、白いカードとの明度の差が小さい。

## タスク

### T1: 検索欄の消去のボタン

- §4.6「検索欄(見出し行)」の消去のボタンを実装する。円は 12pt、× は 16 単位のボックスで
  (5.6, 5.6)–(10.4, 10.4) と (10.4, 5.6)–(5.6, 10.4) の 2 本の線(線幅 1.6、端は丸)である
- 色はシステムの色を使用する(`window-design.html`「実装ノート」)。円は二次的な文字の色、× は不透明な
  背景色にする(カードの色は、ダークでは半透明なので使用しない)
- ボタンは、検索欄の右の内側の余白(8pt)の位置に表示する。表示している間、入力欄の右端はボタンの
  左(間隔 6pt)までにする
- ボタンを押したときの動作(文字の消去、検索の再実行、選択とスクロール位置の扱い)は、キーで検索欄の文字を
  全部削除したときと同じ経路を使用する。判定(ボタンを表示する条件)は Core に実装し、ビューに記述しない
- 日本語入力の変換中(marked text)にボタンを押した場合は、変換中の文字も含めて消去する
- キーの動作(Esc、Enter、↑ / ↓、⌘F)は変更しない

### T2: ポップオーバーの外観

- §4.5「ポップオーバー」のとおり、ポップオーバーを開くたびに、アプリの外観(`NSApp.effectiveAppearance`)を
  ポップオーバーに設定する。`NSPopover` は、外観を設定しない場合、アプリの外観に従わない
  (SDK の `NSPopover.h`: 設定しない場合の外観は `NSAppearanceNameVibrantLight`)
- トレイアイコンの描画(メニューバーの外観に従う)は変更しない

### T3: ライトの一覧の地

- ライトの一覧の地は、システムの背景色に灰色を混ぜた色である。灰色の割合を 6% から 10% に変更する
  (`SurfaceColors.listBackgroundNSColor`)。色の決め方(システムの色から作成する)と、ダークの値は変更しない
- 割合は、実機スモークの結果で調整する

## 完了条件

- `swift build --build-tests -Xswiftc -warnings-as-errors` と `swift test -Xswiftc -warnings-as-errors` が
  警告なしで成功する
- 所有者の実機スモーク:
  1. ポップオーバーとウィンドウのそれぞれで、検索欄に文字を入力すると、右端に消去のボタンが表示される。
     押すと文字が消去されて、一覧が検索なしの表示に戻り、検索欄にフォーカスが残る。文字が無い間は
     表示されない。入力した文字は、ボタンの下に入らない。一覧にフォーカスがある状態(選択中のカードが青)で
     押すと、検索欄にフォーカスが移り、選択中のカードが灰色になる
  2. 日本語入力の変換中に消去のボタンを押すと、変換中の文字も消去され、その文字での検索は実行されない
  3. ライトとダークのそれぞれで、消去のボタンの円と × を判別できる
  4. Settings の Appearance が Dark で、OS の外観がライトのとき、ポップオーバーがダークで表示される
     (Light と OS のダークの組み合わせでも、Appearance の設定に従う。System では OS の外観に従う)。
     ポップオーバーの矢印と、詳細ページの会話ペインも同じ外観になる。ポップオーバーを閉じた状態で
     Appearance を変更すると、次に開いたときに反映される
  5. ライトで、ポップオーバーとウィンドウの一覧の地と、白いカードを判別できる
  6. 変更していない動作: Esc・Enter・⌘F のキーの動作、ダークの一覧の地、トレイアイコンの表示
