## 背景

カードの左端には記号の場所があり、History の行では、スターを付けていない行で空白になる。経過時間は 2 行目の
ラベルの後に表示している。1 列で詳細ページを開く操作は、行の右端の小さい `>` ボタンである。2 列になる幅は、
ポップオーバーの幅の約 2.1 倍である。カードの 3 行は、上から、タイトル、ラベル、最後の発話の順で、
タイトルは未確認の行だけ太字である。会話ペインのヘッダは、1 行目がタイトル、2 行目がパスと経過時間である。これらを、DESIGN.md の仕様に合わせて変更する。

## タスク

### T1: カードの配置

既存実装: `UnifiedListView.swift`(行の描画、区画の見出し)、`RowSymbolView.swift` と `WorkingSpinnerView.swift`(状態記号)、
`SurfaceStyle.swift`(`SurfaceScale` の行の寸法、`SurfaceIcon.star`)、`ShiibarCcCore` の `UnifiedListRows.swift`(行の文字列)。

- カードを、左の 3 行の文字と、右の「記号と時間の列」で構成する(§4.5「一覧は 2 つの区画」)
  - 列の幅は 28pt(文字の大きさ 13 のとき。比率で連動する。§9)。列の中央に、上に記号、下に経過時間を配置する
  - 記号は、Running の行が状態記号(赤バッジを含む)、History の行がスターである。状態記号は 20pt、スターは 16pt(比率で連動)
  - 記号の枠(20pt。状態記号の大きさ)の上端は 1 行目の位置に、経過時間は 3 行目の位置にそろえる
  - 3 行の文字は、どの行も列の手前で終わる(末尾を省略する)。経過時間は省略しない(収まらない場合は、その行の列を広げる)
  - カードの左端の記号の場所は廃止する(文字は、カードの左の余白から始まる)。この配置の変更では、カードの高さは変化しない(行の間隔による高さの変化は T5)
- ラベルの行から経過時間を除く(ラベルだけ。History に残る実行中の会話の `· running` の印は、ラベルの行に残す)。
  最後の発話の先頭の `❯` を廃止する。この 2 つの行の文字列を作成する処理(Core)と、そのテストを変更する
- スターの動作(ホバーで輪郭を表示、クリックで切り替え、ツールチップ、クリックでは行を選択しない)は変更しない。
  スターの大きさは 16pt のままにする(文字の大きさ 13 のとき。比率で連動する)。状態記号(20pt)と中心をそろえて、
  記号と時間の列の上に配置する。クリックに反応する範囲は、状態記号と同じ 20pt にする
- 行の `>` ボタンを削除する(1 列。ボタン、寸法の定数、ツールチップ、行を選択して詳細ページを開く入力の経路のうち、
  使用しなくなるもの)

### T2: View ボタンとキーの案内

既存実装: `UnifiedListState.swift`(`BottomPanelModel`、`BottomPanelButtons`、キーの案内)、`UnifiedListView.swift` と
`ConversationPaneView.swift`(下部パネルの描画)、`UnifiedListKeys.swift`(→ の処理)。

- 1 列の一覧のページの下部パネルに、Branch の左に View ボタンを表示する(§4.6「下部パネル」)。副ボタンの見た目で、
  ラベルは `View`、続けて `→` を、ほかのボタンのショートカットと同じ表示で配置する
- 押すと、選択中の行の詳細ページを開く(一覧にフォーカスがある間の → と同じ処理を実行する)
- View は、ほかのボタンと同じ条件で表示する(行を選択していて、検索欄にフォーカスが無い間)。disabled にはならない。
  詳細ページと 2 列の右の列には表示しない
- キーの案内から `→ Open` を削除する(1 列の一覧のページの、一覧にフォーカスがある間は `↑↓ Move` だけ。§4.5「固定フッター」)
- 表示するかどうかと、ボタンの並びの判定は Core に実装する

### T3: ⌘ + ダブルクリック

既存実装: `MainSurfaceController.swift` と `MainSurfaceModel.swift`(行のクリックとダブルクリックの処理)、Core の対応する入力。

- ⌘ を押しながらのダブルクリックで、Branch を実行する(§4.5「行のダブルクリック」)。⌘ の判定は、2 回目のクリックの時点
- Branch が disabled のときは、選択とフォーカスの移動だけを実行する。⌘ を押しながらの 1 回のクリックは、通常のクリックと同じ
- ダブルクリックのほかの規則(選択の解除を遅らせる処理、3 回以上のクリック)は変更しない

### T4: 2 列になる幅

既存実装: `MainSurfaceConstants.swift`、`TextSize.swift`(`twoColumnPaneAllowance`)、列の幅の計算(Core)。

- 右の列の最小の幅を 360pt にする(§9)。2 列になる幅(既定の幅 + 360pt)と、列の境界のドラッグの範囲が、この値に従う
- 既存のテストの期待値(460、880 など)を、仕様の値に合わせて変更する

### T5: 3 行の順序、太字のタイトル、行の間隔

既存実装: `UnifiedListView.swift`(行の 3 行の描画)、`SurfaceStyle.swift`(`SurfaceScale` の行の寸法)、
`ShiibarCcCore` の `UnifiedListRows.swift`(行の文字列)、`ConversationPaneView.swift` と Core の会話ペインのヘッダ
(`session_id` が空の行で、行のタイトルを表示する処理)。

- 3 行を、上から、ラベル、タイトル、最後の発話の順にする(§4.5「一覧は 2 つの区画」)。ラベルと最後の発話は、
  小さい文字と二次色のまま、タイトルは本文の大きさのままである。History に残る実行中の会話の `· running` の印は、
  ラベルの行(1 行目)に表示する
- タイトルを、どの行も太字にする(未確認の行で使用している太さ)。未確認は、赤バッジだけで示す
  (未確認かどうかでタイトルの太さを変更する処理を削除する)
- タイトルと最後の発話の間隔を 4pt にする(文字の大きさ 13 のとき。比率で連動する。§9)。ラベルとタイトルの間隔は
  変更しない。カードの高さは、間隔の差の分だけ増える
- 記号と時間の列: 記号の枠の上端は 1 行目(ラベル)の位置、経過時間は 3 行目(最後の発話)の位置のままにする。
  経過時間の文字の大きさと色は、ラベルと同じである
- Core の行の型で、行の番号を名前に持つもの(1 行目、2 行目を指す名前)は、内容を表す名前(ラベル、タイトルなど)にする
- `session_id` が空の行の会話ペインのヘッダのタイトルの行は、カードのタイトルの行(2 行目)の文字を表示する(§4.5「行のクリック」)。
  カードの行の順序の変更で、この文字がラベルの行の文字に変化しないようにする(ヘッダの 1 行目は T7)

### T6: 列の数が変化したときのフォーカス

既存実装: `MainSurfaceController.swift`(フォーカスの監視と `focusList`)、`MainSurfaceView.swift`(1 列と 2 列の切り替え)、
`ConversationsSearchField.swift`、Core の `columnsChanged` の処理。

- ウィンドウの幅を変更して、1 列と 2 列が切り替わると、一覧にフォーカスがある状態でも、検索欄にフォーカスが移動する。
  原因は、1 列と 2 列で一覧のページを別々のビューとして作成していて、切り替えのたびに作成される検索欄が、過去の
  フォーカスの依頼(ウィンドウを開いたとき、⌘F)を再度実行することである(§8.59)。1 列と 2 列で同じビューを使用して、
  検索欄を作成し直さないようにする(§4.5「幅による切り替え」の「幅を変更したとき」)
- 検索欄にフォーカスがある状態で変化した場合は、検索欄にフォーカスを保持する(入力中の文字とカーソルの位置を保持する)

### T7: 会話ペインのヘッダの順序と 1 行目の内容

既存実装: `ConversationPaneView.swift`(ヘッダの描画)、`SurfaceStyle.swift`(ヘッダの寸法)、Core の `ConversationPaneModel`。

- 会話ペインのヘッダの 2 行を、1 行目 = フォルダラベルと経過時間(小さい文字・二次色)、2 行目 = タイトル、にする(§4.6)。
  フォルダラベルは、一覧のカードのラベルと同じ文字列(末尾 2 要素)である。ホーム相対のフルパスは表示しない。
  `running` の印は、ヘッダには表示しない。経過時間の書式は変更しない。
  文字の大きさ、太さ、色、2 行の間隔も変更しない。ヘッダの高さ、戻るボタン、位置の表示、前後の会話へ移動するボタンの
  位置と、2 列の右の列のヘッダの上下の中心の位置(§4.5「文字の大きさ」)は変更しない
- `session_id` が空の行のヘッダも、同じ構成にする(1 行目 = 行のラベルと経過時間、2 行目 = 行のタイトルの文字)。
  フルパスの文字列を作成する処理が使用されなくなる場合は、削除する

### T8: 詳細ページの表示中の Tab

既存実装: `MainSurfaceView.swift`(1 列の一覧のページと詳細ページの重なり)、`ConversationsSearchField.swift`、
`MainSurfaceController.swift`(フォーカスの監視)。

- 1 列の詳細ページを表示している間は、一覧のページのビュー(検索欄など)を、Tab と ⇧Tab の移動先にしない(§4.5「キー操作」)。
  詳細ページの表示中に Tab を押しても、検索欄にフォーカスが移動しないこと、アプリが「検索欄にフォーカスがある」と
  判定しないこと(下部パネルのボタンが表示されたままであること)を確認する
- 一覧のページを表示している間と、2 列の間の Tab の動作は変更しない。詳細ページから一覧のページに戻った後は、
  検索欄が、クリック、⌘F、Tab でフォーカスを受け取れる
- 表示していないビューを Tab の移動先から除外する方法は、一覧のページのビューを作成し直さない方法にする
  (検索欄を作成し直すと、過去のフォーカスの依頼が再度実行される — T6)
