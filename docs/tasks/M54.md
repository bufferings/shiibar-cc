## 背景

Running と History の見出しは、行の枠と同じ幅の、角丸の帯である。Starred と Recent の見出しは、文字だけの見出しである。
行の記号と時間の列は、記号と経過時間を列の中央にそろえて表示し、History の行の記号はスターだけである。
会話を一覧から外す操作は無い。索引は、人の発話が 1 つも無い transcript も会話として登録するので、一覧に、文字の無い行、
またはフォルダの名前だけの行が表示される。これらを、DESIGN.md の仕様に合わせて変更する。

タスクは、CLI(T1)とアプリ(T2〜T8)に分かれる。T1 は、アプリのタスクと独立に実装できる。

## タスク

### T1(CLI): 人の発話が無い transcript を、索引に会話として登録しない

既存実装: `crates/shiibar-cc/src/conversations/mod.rs`(`sweep`、`catch_up`)、`db.rs`(スキーマ、`indexed_files`、`replace_conversation`、
`remove_conversation`、`search`、`show`)、`transcript.rs`(`extract`)、`crates/shiibar-cc/src/conversations_cmd.rs`(exit code)。

- 追いつきで読み直したファイルの発話列に、人の発話(役割が user の発話)が 1 つも無い場合は、会話として登録しない。
  その session-id の会話が登録済みの場合は、索引から消す(§4.6「索引の内容」「追いつき」)
- 会話として登録しないファイルの `(パス, mtime, サイズ)` を記録して、変化するまで読み直さない。変化したファイルは、ほかのファイルと同じく読み直し、
  人の発話があれば会話として登録する。消えたファイルの記録は消す
- `search`(クエリの有無に関係なく)は、登録していないファイルを結果に含めない。`show` は、登録していない session-id に対して、
  索引に無い session-id と同じ結果(exit 2)を返す(§4.4)
- スキーマを変更する場合は、スキーマ版を上げる(既存の DB は、版の不一致で全構築される — §4.6「SQLite の規律」)
- `index --json` の進捗(`total`、`done`、`indexed`)の数え方は、読み直したファイルの数のままでよい(会話として登録しなかったファイルを含む)。
  数え方を変更する必要がある場合は、完了報告で提案する。`done` のイベントの `removed` は、索引から消した、登録済みの会話の数である
  (人の発話が無くなって消した会話を含む。会話として登録していないファイルは、記録を消しても数えない。§4.4)
- 出力 JSON の形(§4.4)は変更しない

### T2(アプリ): 見出しの形と色

既存実装: `app/Sources/ShiibarCcApp/UnifiedListView.swift`(区画の見出し、行の枠)、`SurfaceStyle.swift`(`SurfaceColors`、`SurfaceScale`、`SurfaceMetrics`)、
`app/Sources/ShiibarCcCore/UnifiedListRows.swift`(見出しのモデル)。

- Running と History の見出しを、一覧の幅いっぱいの帯にする(左右の余白なし、角を丸めない、上端と下端に 1pt の区切り線、帯の地)。
  高さは 30pt(線を含む。文字の大きさ 13 のとき。線を除いて連動する)。名前の左端を行の文字の左端に、山形の右端を行の記号と時間の列の右端にそろえる
  (§4.5「一覧は 3 つの区画」、§9、`docs/window-design.html`)
- 帯の上と下の間隔は 8pt(文字の大きさに連動しない)。一覧の最初の要素が帯のときは、上の間隔を持たず、見出し行のすぐ下に配置する。
  2 列では、最初の帯の上端の線を引かない。帯は、一覧と一緒にスクロールする
- Starred と Recent の見出しを、文字と線の見出しにする(行数と山形の間の残りの幅に、区切り線の色の 1pt の線。見出しの案内 `Drop here to star` /
  `Drop here to unstar` を表示している間は、行数と案内の間に線を引く)。文字と線の見出しも、名前の左端と山形の右端を、帯と同じ位置にそろえる
  (内側の余白は、左 12pt・右 9pt。`docs/window-design.html` の CSS)
- 見出しのクリックの範囲は、帯では帯の全体、文字と線の見出しでは、これまでと同じ範囲である。閉じている見出しの名前の色、Running の印、行数、
  行のドラッグ中の見出しの強調(文字と線の見出し。角丸 6pt。強調している間も線を表示する)は、これまでの規則のままである
- 検索中の Running と History の見出しは、帯の形のままで、山形と Running の印を表示しない(文字だけの見出しにしない。§4.5「区画の開閉」)
- 色(`docs/window-design.html` の「実装ノート」): 一覧の地のライトの `systemGray` の割合を 5% にする。帯の地を、`systemGray` の不透明度 0.09(ライト)/
  0.12(ダーク)にする。行の枠の地、ダークの一覧の地は変更しない
- 帯の高さ、間隔、名前と山形の位置を計算する値を、テストできる定数または純粋な処理にする

### T3(アプリ): 記号と時間の列と、三点リーダーのボタン

既存実装: `UnifiedListView.swift`(行、記号と時間の列、スター)、`SurfaceStyle.swift`(`SurfaceIcon`、列の幅と記号の大きさ)。

- 記号と時間の列の、記号の枠と経過時間を、列の右端にそろえる(Running の行を含む。§4.5「一覧は 3 つの区画」)
- 通常の一覧の History の行は、列の上を、左からスターの枠、三点リーダーの枠(間隔 4pt。文字の大きさに連動しない)にする。列の幅は最小 44pt
  (文字の大きさ 13 のとき)。Running の行は、状態記号の枠だけで、最小 28pt のままである(§9)
- 三点リーダーは、横に並ぶ 3 つの点(16pt。形は `docs/window-design.html` の `i-more`)で、二次色で、常に表示する。クリックに反応する範囲は記号の枠で、
  ツールチップは `More`、アクセシビリティの名前は `More actions` である
- 三点リーダーをクリックすると、ボタンの下に、右端をボタンの右端にそろえて、OS の標準のメニューを表示する。項目は `Archive` の 1 つである(T5)。
  メニューを開いている間は、三点リーダーの枠に、淡い灰色の地(角丸 5pt)を表示する。
  メニューの項目(題名、enabled)は、表示と分けた純粋な値にする(`HeaderMenu.entries` と同じ構成)。テストは、メニューを表示しない。
  クリックでは、スターと同じく、行を選択せず、ダブルクリックの動作を実行せず、行のドラッグを開始しない。key でないウィンドウでは、ウィンドウを key にして、
  同じクリックでメニューを表示する(§4.6「Archive」)
- 見出しのクリックから始まる連続したクリックの 2 回目以降が、三点リーダーの上でも何もしないこと(§4.5「区画の開閉」)

### T4(アプリ・Core): Archive の保存

既存実装: `app/Sources/ShiibarCcCore/UnifiedListRows.swift`(スターの順序付きの一覧と、その保存)、`MainSurfaceConstants.swift`(UserDefaults のキー)。

- Archive した会話の session_id の、順序付きの一覧(先頭が、最後に Archive した会話)を、スターと同じ方法で、注入された UserDefaults に保存する(§4.6「Archive」の「保存」)。
  UserDefaults のキーの名前は、実装で決める(既存のスターのキーの命名に合わせる)
- 操作: Archive(先頭に追加。すでにある場合は変更しない)/ Unarchive(一覧から外す)/ 一覧に無い session_id の破棄(クエリが空の一覧を取得した時点)
- 保存済みの値が想定の形でない場合は、空の一覧として扱う。同じ session_id が複数ある場合は、最初の 1 つだけを使用する
- 純粋な値の型と、保存の処理を分ける(スターの実装と同じ構成にする)

### T5(アプリ・Core): 通常の一覧からの除外と、Archive / Unarchive の動作

既存実装: `app/Sources/ShiibarCcCore/UnifiedListState.swift`(イベントと状態、区画への振り分け、Recent の上限、スターの変更、選択の規則)、
`UnifiedListRows.swift`(行の作成)。

- 通常の一覧の Starred と Recent から、Archive した会話を除く。Recent の上限(§9)は、除いた後の並びに適用する。検索中も同じである(§4.6「Recent の区画」「検索の適用範囲」)。
  空状態の判定では、Archive した会話を数えない
- `Archive`: その会話を Archive の一覧の先頭に追加し、スター付きの場合は、スターの順序付きの一覧から外す。search を再実行せずに、表示に反映する。
  選択中の行を Archive したときは、選択なしにする
- live の会話の行(`· running` の印がある History の行)は、メニューの `Archive` を disabled にする。メニューを開いた後に live になった会話で
  `Archive` を選択した場合は、何も変更しない(Archive せず、スターも外さない)
- live の会話は、Archive の一覧に含めない: Archive した会話が live である場合(session_id が同じ Running の行がある、または search の結果が
  その会話を `live: true` と報告している)は、Archive を解除する。判定は、出来事ではなく状態の規則として実装する: エージェントの一覧、search の結果、
  Archive の一覧のどれかが変化するたびに判定する(アプリの起動後の最初の一覧、Running の行が後から session_id を持った場合、
  Running の行が現れる前に開いたメニューで `Archive` を選択した場合を含む。§4.6「Archive」の「Archive の自動の解除」)
- `Unarchive`: Archive の一覧から外す。会話は、通常の一覧の Recent の、新しい順の位置に表示する(スターは戻さない)

### T6(アプリ): Archive の一覧

既存実装: `UnifiedListState.swift`、`UnifiedListView.swift`、`MainSurfaceModel.swift`、`MainSurfaceController.swift`(ポップオーバーとウィンドウを閉じる処理)、
`ConversationsSearchField.swift`(プレースホルダ)、`MainSurfaceController.swift` の `HeaderMenu`、`app/Sources/ShiibarCcCore/UnifiedListKeys.swift`(Esc)。

- 一覧の表示に、通常の一覧と Archive の一覧の 2 つの状態を追加する。状態は、ポップオーバーとウィンドウで共通で、保存しない(§4.6「Archive の一覧」)
- Archive の一覧は、先頭に帯の見出し `‹ Archived`(左向きの山形、名前、行数。右端の山形なし)を表示し、その下の 1 つの枠の中に、
  Archive した会話のうち search の結果にあるものを、保存している一覧の順(Archive した時刻の新しい順)に表示する。Running、Starred、Recent の区画は表示しない。
  表示する行の上限、`N more` の行、見出しの `first 100` は、Recent と同じ規則である
- 行は、記号と時間の列の上が三点リーダーだけである(スターなし。列の幅は最小 28pt)。メニューの項目は `Unarchive` である(live の会話は Archive を自動で解除するので、Archive の一覧に `· running` の印がある行は無い)。
  行の選択、クリック、ダブルクリック、↑ / ↓、詳細ページ、会話ペイン、下部パネルは、通常の一覧の History の行と同じである。行はドラッグできず、ドラッグできない理由も表示しない
- 選択中の行が、`Unarchive` または Archive の自動の解除で Archive の一覧から外れたときは、選択なしにする(その結果、通常の一覧に戻る場合を含む。
  1 列の詳細ページでは、一覧のページに戻る)
- Archive の一覧は、表示するたびに、最上部から表示する。通常の一覧に戻ったときは、切り替える前の、通常の一覧のスクロール位置に戻す
- 最初の search の結果を受け取る前は、帯の見出しに行数を表示せず、帯の下は、通常の一覧と同じ、取得中の表示にする
- ⌄ メニューに `Archived` を追加する(`Setup Check…` の下のセパレーターの後、`Clear badges` の前)。Archive した会話が無い間は disabled(保存している Archive の一覧で判定し、search の結果を待たない)、
  Archive の一覧を表示している間はチェックマークを付け、選択すると通常の一覧に戻る(§4.5「⌄ メニュー」)
- 通常の一覧に戻る操作: 帯 `‹ Archived` のクリック(帯の全体。キーのフォーカスを変更しない。帯のクリックから始まる連続したクリックは、2 回目以降は何もしない)、Esc(戻る操作だけを実行して、ポップオーバーを閉じない。
  日本語入力の変換中の Esc は、これまでどおり入力に渡す。
  行のドラッグ中の Esc の規則は、通常の一覧だけに関係するので変更しない)、⌄ メニューの `Archived`。Archive した会話が無くなったときも、通常の一覧に戻る
- ポップオーバーまたはウィンドウを閉じたとき(表示の形の切り替え、Resume / Branch / Jump の成功でポップオーバーを閉じたとき、トレイアイコンとホットキーで閉じたときを含む)は、
  通常の一覧に戻す
- 検索欄のプレースホルダを、Archive の一覧の間は `Search archived` にする。クエリが有効な間は、search の結果のうち Archive した会話だけを表示し、
  該当する会話が無いときは、帯の見出しの下に `No matching conversations` を表示する。切り替えで検索欄の文字を変更しない
- 切り替えた後の一覧に、選択中の行が無いときは、選択なしにする(1 列の詳細ページでは、一覧のページに戻る)
- 記憶している区画の開閉の状態は、Archive の一覧に適用せず、Archive の一覧の表示で変更しない

### T7(アプリ): Running の行の会話が索引に無い場合の会話ペイン

既存実装: `MainSurfaceModel.swift`(show の結果の処理)、`ConversationPaneView.swift`、`UnifiedListState.swift`(`ConversationPaneModel.noMessagesText`)。

- Running の行の会話で show が exit 2 のときは、エラーの 1 行ではなく、メッセージ面の中央に `No conversation to show` を表示する(§4.6「会話ペインの表示」)。
  History の行と Archive の一覧の行の exit 2 は、これまでどおりエラーの 1 行を表示する
- `No conversation to show` を表示している間は、自動では更新しない。その行を選択し直したとき、または Refresh を実行したときに、show を再度実行する

- `cargo build`、`cargo test`、`cargo clippy --all-targets` が、警告なしで成功する
- `swift build --build-tests -Xswiftc -warnings-as-errors` と `swift test -Xswiftc -warnings-as-errors` が
  警告なしで成功する
- 実機スモーク(担当は所有者):
  1. Running と History の見出しが、一覧の幅いっぱいの帯で表示される。最初の帯が、見出し行のすぐ下にある。Starred と Recent の見出しに、細い線が表示される。
     ライトとダークの両方で、帯、行の枠、一覧の地を判別できる
  2. 2 列のウィンドウで、帯が左の列の幅いっぱいに表示され、見出し行の下の区切り線と、最初の帯の上端が、2 本の線にならない
  3. 見出しのクリックで区画が開閉する。閉じている Running の赤い点、閉じている見出しの名前の色、行数が、変更の前と同じ規則で表示される。
     検索中は、帯に山形が表示されず、クリックしても開閉しない
  4. 行のドラッグで、見出しの案内(`Drop here to star` / `Drop here to unstar`)、見出しの強調、移動先の線が表示され、ドロップの結果が変更の前と同じである
  5. History の行の右上に、星と三点リーダーが表示される(Recent の行の星は、ホバーの間だけ表示される)。Running の行の状態記号、三点リーダー、経過時間の右端がそろっている。
     文字の大きさ 9 と 18 でも、記号と文字が重ならない
  6. 三点リーダーを押すと、`Archive` のメニューが表示される。行は選択されない。`Archive` を選択すると、その行が一覧から消える。
     スター付きの行を Archive すると、Starred から消える。`· running` の印がある行では、`Archive` を選択できない
  7. ⌄ メニューの `Archived` が、Archive した会話が無い間は選択できず、ある間は選択できる。選択すると、`‹ Archived` の帯と、Archive した会話だけが、
     Archive した順(新しいものが上)に表示される。検索欄に `Search archived` と表示される
  8. Archive の一覧で、行を選択して、会話を読むこと、Resume、Branch ができる。三点リーダーのメニューの `Unarchive` で、行が Archive の一覧から消え、
     通常の一覧の Recent に表示される。最後の 1 つを Unarchive すると、通常の一覧に戻る
  9. Archive の一覧から、帯のクリック、Esc、⌄ メニューの `Archived` で、通常の一覧に戻る。ポップオーバーでは、1 回目の Esc でポップオーバーが閉じない。
     ポップオーバーまたはウィンドウを閉じて開き直すと、通常の一覧が表示される
  10. 通常の一覧の検索で、Archive した会話が表示されない。Archive の一覧の検索で、Archive した会話だけが表示される。切り替えたときに、検索欄の文字が残る
  11. Archive した会話を Archive の一覧から Resume すると、その会話の Archive が解除される。ポップオーバーは閉じ、次に開くと、通常の一覧の Running に表示される。
      ウィンドウでは、Archive の一覧からその行が消えて、選択なしになり、通常の一覧に戻ると Running に表示される。終了した後は Recent に表示される(Archive の一覧には表示されない)。
      選択中の行を `Unarchive` したときも、選択なしになる
  12. アプリを再起動しても、Archive した会話が、通常の一覧に表示されず、Archive の一覧に表示される
  13. 発話を送らずに終了したセッション(Claude Code を起動して、スラッシュコマンドだけを実行して終了する)が、一覧に表示されない。
      同じセッションを再開して発話を送ると、一覧に表示される。発話をまだ送っていない実行中のセッションは、Running に表示され、選択すると `No conversation to show` が表示される。
      その表示の間に発話を送り、行を選択し直す(または Refresh を実行する)と、会話が表示される
  14. 行の選択、ダブルクリック、Jump / Resume / Branch、検索、Refresh、表示の形の切り替えが、変更の前と同じように動作する
