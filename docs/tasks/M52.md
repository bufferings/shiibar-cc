## 背景

トレイアイコンのクリックとグローバルホットキーは、ウィンドウを開いていない間はポップオーバーを開閉し、ウィンドウを開いている間は
ウィンドウを前面に移す(閉じない)。ウィンドウは `Open in window` でだけ開き、ウィンドウを閉じると、次のクリックはポップオーバーを開く。
見出し行には ⟳ のボタンがあり、Refresh は ⟳ と ⌘R で実行する。⟳ は、実行中に回転する。
これらを、DESIGN.md の仕様に合わせて変更する。

## タスク

### T1: 表示の形を記憶する

既存実装: `ShiibarCcCore` の `MainSurfaceConstants.swift`(`MainSurfaceDefaultsKeys`)。`ShiibarCcApp` の
`MainSurfaceController.swift`(`openWindow()`、`windowWillClose(_:)`)、`MainSurfaceModel.swift`、`ShiibarCcMenuBarApp.swift`(起動の処理)。

- 表示の形(ポップオーバーの形 / ウィンドウの形)を表す型を Core に追加し、UserDefaults に保存する(§4.5「表示の形」)。
  保存には、新しいキーを使用する(`MainSurfaceDefaultsKeys` に追加する)
- 保存値が無い場合と、値が不正な場合(文字列でない値、定義していない文字列)は、ポップオーバーの形にする
- 形を変更する操作は、`Open in window`(ウィンドウの形にする)と `Open in popover`(ポップオーバーの形にする)だけである。
  ウィンドウを閉じる処理(赤ボタン、⌘W、トレイアイコンのクリック、グローバルホットキー)では、形を変更しない
- 形は、変更した時点で保存する
- 起動時には、どちらの形でも、ポップオーバーもウィンドウも表示しない(ウィンドウの形で終了した後の起動でも、ウィンドウを開かない)

### T2: トレイアイコンのクリックとグローバルホットキーの動作

既存実装: `ShiibarCcCore` の `GlobalShortcutRecorder.swift`(`SurfaceToggleAction.decide(windowOpen:popoverShown:)`)。`ShiibarCcApp` の
`MainSurfaceController.swift`(`toggleSurface(from:)`、`showPopover(openedByHotKey:)`、`openWindow()`、`raiseWindow()`、`focusAfterHotKey()`)、
`AppState.swift`(通常アプリへの切り替えと、accessory に戻す処理)。

- 動作の判定を、Core の純粋な処理にする。入力は、表示の形、ポップオーバーを表示しているかどうか、ウィンドウを開いているかどうか
  (最小化している場合は、開いている)、ウィンドウが前面かどうか、の 4 つである。結果は、ポップオーバーを開く / ポップオーバーを閉じる /
  ウィンドウを開く / ウィンドウを前面に移す / ウィンドウを閉じる、の 5 つである(§4.5「トレイアイコンのクリック」の表)
- 判定は、次の順序で 1 つに決める(仕様では発生しない入力の組み合わせ — ポップオーバーの形でウィンドウを開いている、
  ウィンドウの形でポップオーバーを表示している — も、この順序で決まる):
  1. ポップオーバーを表示している場合は、ポップオーバーを閉じる
  2. ウィンドウを開いている場合は、前面なら閉じ、前面でなければ前面に移す
  3. どちらでもない場合は、表示の形によって、ポップオーバーの形ならポップオーバーを開き、ウィンドウの形ならウィンドウを開く

  ウィンドウを開いていない場合は、「前面である」の入力の値を使用しない
- 「ウィンドウが前面である」は、次の 4 つの条件の全部が成立している状態である: アプリがアクティブである / このウィンドウが key である /
  ウィンドウを最小化していない / ウィンドウが現在の Space にある(§4.5「トレイアイコンのクリック」)。App の側は、この 4 つの条件だけから導出する
- 判定には、ステータスアイテムのアクション、またはホットキーの処理を実行する時点の、この 4 つの条件の値を使用する。
  この時点の値が、クリックまたは押下の直前の状態と一致することは、実機スモーク(4、5、7)で確認する。
  実装者は、確認のためにアプリを起動しない
- 閉じている状態からウィンドウを開く処理は、`Open in window` でウィンドウを開く処理と同じにする(通常アプリへの切り替え、位置と大きさの復元、
  History の再取得 — §4.6「History を再取得する契機」)
- 開いたときのフォーカス: トレイアイコンのクリックで開いたときは、ポップオーバーを開いたときと同じである(1 列の一覧のページと 2 列では検索欄、
  1 列の詳細ページでは会話ペイン)。ホットキーで開いたとき、またはホットキーで前面に移したときは、一覧にフォーカスを移す(§4.5「グローバルホットキー」)。
  トレイアイコンのクリックで前面に移したときは、フォーカスを変更しない(§4.5「ウィンドウ」)。
  閉じている状態からホットキーで開いた場合も、ウィンドウが key になった後に、一覧にフォーカスがある状態にする
  (通常アプリへの切り替えは、アクティブ化を後の時点で実行する。フォーカスの移動が、その前に実行されて無効にならないこと)。
  一覧にフォーカスを移すのは、開いてから 1 秒以内にウィンドウが key になった場合だけである(§9。その後の key の変化は、
  利用者の操作によるものとして扱い、フォーカスを変更しない)
- 前面のウィンドウを閉じる処理は、赤ボタンで閉じたときと同じ経路にする(accessory に戻る。検索欄の文字・行の選択・表示中のページは保持する)。
  アプリをアクティブにする処理と、ほかのアプリをアクティブにする処理は、追加しない。閉じた後に、キーの入力が、直前に前面だったアプリに
  戻ること(§4.5「ウィンドウ」)は、実機スモーク(6)で確認する
- ポップオーバーの形の動作(開閉と、ポップオーバーを閉じた直後のクリックで再度開かない処理)は、変更しない
- Dock のアイコンのクリックと ⌘Tab は、ウィンドウを前面に移すだけである(閉じない。変更しない)
- 通常アプリになる条件は、T3 の `Open in popover` の場合を除いて、変更しない(§4.5「ウィンドウを開いている間だけ、アプリは通常アプリになる」)

### T3: 見出し行

既存実装: `ShiibarCcApp` の `UnifiedListView.swift`(`HeaderRowView`、`RefreshButton`)、`SurfaceStyle.swift`(見出し行のアイコンの定義)、
`MainSurfaceModel.swift`(`openInWindowClicked()`)、`MainSurfaceController.swift`。

- ポップオーバーの見出し行は 検索欄 / `Open in window` / ⌄、ウィンドウの見出し行は 検索欄 / `Open in popover` / ピン / ⌄ にする(§4.5「見出し行」)
- ⟳ のボタンを削除する
- `Open in popover` のボタンを追加する。アイコンは `docs/window-design.html` の `i-popover`(16 の格子)である。
  大きさ、線の太さ、背景の表示(静止時は背景なし、ホバー、押下)は、`Open in window` のボタンと同じにする。ツールチップは `Open in popover`
- `Open in popover` は、ウィンドウを閉じて、表示の形をポップオーバーの形にし、ポップオーバーを開く。開いたポップオーバーのフォーカスは、
  トレイアイコンのクリックで開いたときと同じである
- `Open in popover` で開いたポップオーバーは、開いたままにする。そのために、`Open in popover` でウィンドウを閉じたときは、accessory に戻す処理を
  実行せず、開いたポップオーバーを閉じた時点で実行する(§4.5「ウィンドウを開いている間だけ、アプリは通常アプリになる」)。
  処理の順序は、ウィンドウを閉じる → 表示の形を変更して保存する → ポップオーバーを開く、である(ウィンドウを閉じる処理で、
  保留している選択の解除を取り消す — §4.5「行のダブルクリック」)。このポップオーバーから `Open in window` でウィンドウを開いたときは、
  通常アプリのまま、ウィンドウを開く(通常アプリへの切り替えを、再度実行しない)。非アクティブ化を一定時間無視する処理は、使用しない
- 画面(ポップオーバー / ウィンドウ)ごとの見出し行のボタンの並びを作成する処理を、テストできる純粋な処理にする
- `Open in window` は、ポップオーバーを閉じて、表示の形をウィンドウの形にし、ウィンドウを開く
- 形を切り替えても、検索欄の文字・行の選択・表示中のページ・スクロール位置は、既存の規則のまま保持する
  (§4.5「ポップオーバーとウィンドウは 1 つの状態を共有する」)
- 見出し行の変更で、一覧のページと検索欄(`ConversationsSearchField`)を再作成しない。`ColumnSwitchFocusTests.swift` が成功する状態を保つ

- メッセージ行の一時表示の文言(`Refreshing…` / `✓ Refresh done` / `Refresh failed`)と表示時間(§9)、実行中の再実行を無視する動作、

  警告なしで成功する
- 実機スモーク(担当は所有者):
  1. 保存値が無い状態(ポップオーバーの形)で、トレイアイコンのクリックとホットキーが、ポップオーバーを開閉する
  2. `Open in window` の後にウィンドウを閉じて(赤ボタン、⌘W)、トレイアイコンのクリックで、ウィンドウが開く(ポップオーバーは開かない)
  3. ウィンドウの形でアプリを終了して起動した直後は、何も表示されない。トレイアイコンのクリックまたはホットキーで、ウィンドウが開く
  4. ウィンドウが前面のときに、トレイアイコンのクリックで、ウィンドウが閉じる
  5. ウィンドウが前面のときに、ホットキーで、ウィンドウが閉じる
  6. トレイアイコンのクリックまたはホットキーでウィンドウを閉じた後、キーの入力が、直前に前面だったアプリ(ターミナルなど)に戻り、
     そのまま入力を続けられる
  7. ほかのアプリが前面のときに、トレイアイコンのクリックとホットキーで、ウィンドウが前面に移る(閉じない)。ウィンドウを最小化しているときと、
     別の Space にあるときも同じである(Space は切り替わらない)
  8. ピンが ON で、ターミナルで作業している状態からホットキーを押すと、1 回目で一覧にフォーカスが移り、2 回目でウィンドウが閉じる
  9. Settings ウィンドウが key のときにホットキーを押すと、ウィンドウが前面に移る(閉じない)
  10. ホットキーで開いたときと、ホットキーで前面に移したときは、一覧にフォーカスがある。トレイアイコンのクリックで、
      閉じている状態から開いたときは、検索欄にフォーカスがある。トレイアイコンのクリックで前面に移したときは、フォーカスの位置が変化しない
  11. `Open in popover` で、ウィンドウが閉じてポップオーバーが開き、検索欄の文字と行の選択が保持される。ポップオーバーは、開いたままである。
      その後のトレイアイコンのクリックとホットキーは、ポップオーバーを開閉する
  12. 見出し行の並びが、ポップオーバーは 検索欄 / `Open in window` / ⌄、ウィンドウは 検索欄 / `Open in popover` / ピン / ⌄ である。
      `Open in popover` のアイコンの形とツールチップを、ライトとダークで確認できる。ウィンドウの最小の幅でも、見出し行が収まる
  13. ⌄ メニューの Refresh(右に ⌘R)で、メッセージ行に `Refreshing…` と結果が表示される。⌘R でも同じ動作をする
      (ポップオーバーとウィンドウの両方)。Refresh の実行中にメニューを開くと、項目が `Refreshing…` で、選択できない
      (実行の時間が短く、実行中にメニューを開けない場合は、確認しない。この状態は、テストで確認する)
