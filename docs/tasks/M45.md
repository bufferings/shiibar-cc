## 背景

一覧を開く操作は、トレイアイコンのクリックだけである。利用者が登録したキーの組み合わせで、
他のアプリが前面にある間も一覧を開けるようにする。

## タスク

### T0: API の確認

- 実装の前に、`RegisterEventHotKey` が開発マシンの macOS と Swift のツールチェーンで動作することを、
  リポジトリの外に作成した最小のプログラムで確認する(登録の成功、他のアプリが前面にある間の受信、
  登録の解除、同じ組み合わせの二重登録が拒否されること)。確認した方法と結果を、完了報告に記載する
- 動作しない場合は、実装を中止して報告する(代わりの方法を実装しない)
- 外部のパッケージは追加しない

### T1: ホットキーの登録と動作

- §4.5「グローバルホットキー」のとおりに実装する。押したときの分岐は、トレイアイコンのクリックと同じ処理を使用する
- フォーカスの規則(一覧にフォーカスを移す。選択なしの場合は先頭の行を選択する。行が無い場合は検索欄。
  詳細ページでは会話ペイン)の判定は、Core の状態機械に実装する。ビューとコントローラに判定を記述しない
- 起動時に、保存済みの組み合わせを登録する。登録に失敗した場合は、保存した値を保持したまま、未登録として動作する
- ホットキーの登録と解除は、テストで差し替えられる形(プロトコルまたはクロージャ)にする

### T2: Settings の記録欄

- §4.5「Settings ウィンドウ」の General に **Global shortcut** を追加する。文言・検証・エラーの表示は仕様のとおり
- 組み合わせの検証(登録できる条件)、表示用の文字列の生成、UserDefaults への保存形式は、Core に実装する
- 記録中は、ホットキーの登録を一時的に解除する。記録を終了または中止した時点で、有効な登録に戻す
- 記録中のキーイベントは、Settings ウィンドウの他のショートカット(⌘W、⌘, など)よりも先に記録欄が受け取る

### T3: 文書

- `README.md` に、ホットキーの登録方法と動作を記載する(英語)
- この指示書の T0 の結果が §7 に記載する内容(対象の macOS での確認結果)を含む場合は、完了報告で提案する
  (DESIGN.md は編集しない)

## テスト要求

- Core: 組み合わせの検証(修飾キーなし / ⇧ だけ / ⌃・⌥・⌘ のいずれかを含む / ファンクションキー単独)、
  表示用の文字列(修飾キーの順序は ⌃ ⌥ ⇧ ⌘)、保存形式の往復、解釈できない保存値は未登録として扱うこと
- Core: ホットキーの動作の分岐(ウィンドウの有無 × ポップオーバーの開閉)と、フォーカスの規則
  (選択あり / 選択なし / 行なし / 詳細ページ)
- App: 登録の差し替え(spy)で、起動時の登録、記録中の一時解除と復元、登録の拒否時に以前の登録を
  保持すること、× での解除を確認する
- テストは、実際のホットキーを登録しない。実際の UserDefaults の標準ドメインを使用しない
- 既存のテストを弱めない。docs/ 以外に日本語を記述しない

## 完了条件

- `swift build --build-tests -Xswiftc -warnings-as-errors` と `swift test -Xswiftc -warnings-as-errors` が
  警告なしで成功する
- 所有者の実機スモーク:
  1. Settings の Global shortcut で組み合わせ(⇧ を含むものを含む)を記録でき、× で解除できる
  2. 他のアプリが前面にある間にホットキーを押すと、ポップオーバーが開き、一覧にフォーカスがある
     (選択中の行が青で表示され、↑ / ↓ と Enter が動作する)。もう一度押すと閉じる
  3. ウィンドウを開いている間にホットキーを押すと、ウィンドウが前面に移り、一覧にフォーカスがある
  4. アプリを再起動した後も、登録したホットキーが動作する
  5. 日本語入力が有効な状態と、フルスクリーンのアプリが前面にある状態でも、ホットキーが動作する
  6. ⌃ / ⌥ / ⌘ を含まない組み合わせ(ファンクションキー以外)を記録できず、案内が表示される
