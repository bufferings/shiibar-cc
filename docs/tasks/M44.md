## 背景

メニューバーのドロップダウン、Agents ウィンドウ、Conversations ウィンドウの 3 つの画面を、
ポップオーバーとウィンドウの 2 つに置き換える(§8.49)。2 つの画面は同じレイアウトと 1 つの状態を共有し、
実行中のセッション(Running)と過去の会話(History)を 1 つの一覧に表示する。
会話の全文は、既存の会話ペイン(WKWebView)を引き続き使用する。

## タスク

### T1: Core — 一覧・選択・キー・表示文字列のロジック

- **行の構成**(§4.5「Running の行」、§4.6「History の区画」): daemon の一覧と search の結果から、
  Running と History の行(3 行の文字・状態記号・未確認・選択時に下部パネルに表示するボタンの種類と有効 / 無効・ツールチップ)を
  導出する。Running は `created_at` の降順。History は Running と `session_id` が一致する会話を除き、
  スター付きを先、それぞれ `updated_at` の降順。検索中の Running の区画の絞り込みと、区画の見出しの行数
  (§4.6「検索の適用範囲」)、History の表示の上限と末尾の 1 行(§4.6「History の区画」、§9)、スターの規則(§4.6「スター」: 保存した集合の整理、Running に表示している間の扱い)を含む
- **選択の状態遷移**(§4.5「行の選択」): 0 行または 1 行。利用者の操作だけが行を選択する。
  選択中の行が一覧から無くなったときは選択なし。Running の行が終了したときの保持の規則を含む。
  表示中のページ(一覧 / 詳細)と、幅による列の数の切り替えも、同じ状態の型で扱う
- **キーの解釈**(§4.5「キー操作」の表): キーと修飾キーと現在の状態(フォーカスの位置 = 検索欄か一覧か・
  列の数・ページ・行の有無・選択の有無・ボタンの有効 / 無効・日本語入力の変換中かどうか)から、
  実行する操作を返す純粋な関数。フォーカスの移動(一覧へ / 検索欄へ)も操作の結果として返す。
  1 列の詳細ページの ↑ / ↓ は、会話ペインに渡す操作(会話のスクロール)として返し、
  ⌥↑ / ⌥↓ は前後の会話への切り替えとして返す。
  表に割り当てのないキーは、フォーカスのあるビューにそのまま渡す。既存の `ConversationsKeyCommands`(文字サイズ・ヒットの移動・検索欄へのフォーカス)と統合する
- **キーの案内**(§4.5「固定フッター」、§4.6「下部パネル」。移動のキーだけ。検索欄にフォーカスがある間は `↩ List` だけ、
  一覧にフォーカスがある間の `→ Open` は選択で決まる)、
  **下部パネルのボタンの中のショートカットの記号**(`↩` / `⌘↩`。検索欄にフォーカスがある間は表示しない)と、**メッセージ行の優先順位**(§4.6)の文字列の導出
- **下部パネルのボタンの状態**(§4.6)。既存の `ConversationAction` を、Branch と Running の行に対応させる
- **ポップオーバーの高さ**(§4.5「ポップオーバー」、§9): 最小 / 最大の制限と、ドラッグ中に初回の高さへ
  固定する判定
- **search の結果のデコード**に `last_prompt` を追加する
- 使用しなくなる Core の型(状態ごとのグループ化・並び替えの選択・ドロップダウンの高さと位置)と、
  そのテストを削除する。引き続き必要な値とロジック(Running の行の 1 行目の導出、`created_at` の降順、
  経過時間の再取得の間隔、ピンの既定値)は、新しい構成に合わせて名前を変更または移動して残す。トレイアイコンのロールアップは変更しない

### T4: 一覧と会話ペインのビュー

- **レイアウト**(§4.5「幅による切り替え」): 1 列(一覧のページ ⇔ 詳細ページ。スライド)と 2 列。
  幅を変更したときの規則を含む
- **一覧のページ**: 見出し行(検索欄 / ⟳ / `Open in window` またはピン / ⌄)、Running と History の区画、
  カードの行(状態記号またはスター・3 行の文字・1 列では右端の `>` ボタン。実行のボタンは行に配置しない)、
  ホバーと選択の表示(選択中のカードは、ポップオーバーまたはウィンドウが key で、かつ一覧にフォーカスがある間は青、検索欄にフォーカスがある間と、ウィンドウが key でない間は灰色 — §4.5「行の選択」)、空状態、固定フッター(警告行・メッセージ行・キーの案内。1 列では、キーの案内と
  選択中の行の実行のボタンを下部パネルに配置する — §4.5「実行のボタン」「固定フッター」、§4.6「下部パネル」)。既存の `RowSymbolView`・検索欄・⟳ のボタン・
  警告行の内容は再利用してよい
- **表示中の更新**(§4.5): スピナーと経過時間の再取得のタイマーは、ポップオーバーまたはウィンドウを表示している間だけ
  動作させる。通知の許可の判定も、表示するたびに再評価する
- **行のクリックと `>` ボタン**(§4.5「行のクリック」「行の `>` ボタン」): 行のクリックは選択だけで、
  詳細ページを開かない。青で表示している選択中の行のクリックは選択を解除する。灰色で表示している選択中の行の
  クリックは、選択を解除せず、一覧にフォーカスを移す(ウィンドウが key でなかった場合は、key にする)。
  この判定には、マウスのボタンを押した時点の表示を使う(クリックの処理の途中で、ウィンドウが key になったり
  検索欄のフォーカスが外れたりしても、押した時点の表示で判定する)。行のクリックと `>` ボタンは一覧にフォーカスを移す。
  1 列で詳細ページを開くのは `>` ボタンと、一覧にフォーカスがある間の → である
- **行のダブルクリック**(§4.5「行のダブルクリック」): 行を選択し、一覧にフォーカスを移して、Jump(Running の行)
  または Resume(History の行)を実行する(一覧にフォーカスがある間の Enter と同じ。対応するボタンが disabled のときは、
  選択とフォーカスの移動だけ)。行の状態(未選択・青・灰色)による違いは無い。ダブルクリックでは選択を解除しないので、
  青で表示している選択中の行のクリックによる選択の解除は、マウスのボタンを押してからシステムのダブルクリックの間隔
  (`NSEvent.doubleClickInterval`)が経過した時点で実行する。未選択の行の選択と、灰色の行へのフォーカスの移動は遅らせない。
  ダブルクリックの判定には、システムのクリック回数(`NSEvent.clickCount`)を使う。2 回目のクリックが別の行に当たったときは、
  その行の通常のクリックとして扱う。3 回以上の連続したクリックは、Jump / Resume を再実行しない。
  待機中の選択の解除は、2 回目のクリック・他の操作による選択またはページの変更・画面を閉じる操作で取り消す。
  判定と待機中の選択の解除は Core に置き、タイマーはモデルに注入する(テストは実際の間隔を待たない)
- **選択した行を表示範囲に入れるスクロール**(§4.5「行の選択」)と、スターのクリックで行を選択しない規則(§4.6)
- **1 列の詳細ページ**では、警告行とメッセージ行を下部パネルのすぐ上に表示する(§4.5「固定フッター」)
- **会話ペイン**: ヘッダ(1 列では戻るボタン・位置・前後の会話へのボタン)、検索バー行(1 列では左端に
  `Matches for “tag”` の文、右端にカウンタと ‹ ›)、
  メッセージ面、下部パネル(Branch と主ボタン。1 列ではキーの案内。1 列の一覧のページと同じビューを使用し、
  ボタンの位置と大きさを揃える)。選択なし / `session_id` が空の行の表示(§4.5)
- **キー操作**: T1 の関数を、ポップオーバーとウィンドウのキーイベントに接続する。フォーカスのあるビューより
  先に処理し、日本語入力の変換中はすべてのキーを日本語入力に渡す。検索欄にフォーカスがあるかどうかを
  キーの解釈の入力にする。「一覧にフォーカスを移す」は検索欄の first responder を外す(カーソルが消える)。
  一覧にフォーカスがある間の文字の入力と Delete は何もしない。会話ペインにフォーカスがあるときは、
  そのキーを会話ペインに渡す(Space によるスクロールなど)。それ以外では、キーを捨てる(警告音を鳴らさない)。
  1 列の詳細ページの ↑ / ↓ は、会話ペインにフォーカスが無いとき(ヘッダや下部パネルのボタンを押した後など)も、
  会話ペインにフォーカスを移してから渡し、会話をスクロールする。メッセージ面のページは、キーで内側のスクロール領域が
  スクロールするようにする(Space と Page Up / Page Down も同じ)
- **検索欄**: 地(カードの色 + 1px の枠・角丸 6)と虫眼鏡のアイコンはアプリが描画し、その中に枠なしの入力欄を配置する
  (§4.6「検索欄」。大きさは `docs/window-design.html` の `.search`: 高さ 24 = 見出し行のボタンと同じ)。
  地のどこをクリックしても入力欄にフォーカスが移る
- **操作の実行**: Jump(`focus`)、Resume、Branch(`resume --fork`)、スター。成功 / 失敗のときの
  ポップオーバーの開閉とエラーの表示(§4.5「ポップオーバー」、§4.6)
- **再取得の契機**(§4.6「History を再取得する契機」)と、開いたときの index の実行(§4.6)を接続する
- 使用しなくなるビューと ViewModel(ドロップダウン・Agents ウィンドウ・Conversations ウィンドウ用)と、
  そのテストを削除する。該当なしのシート(Jump の失敗時のアラート)も削除する
