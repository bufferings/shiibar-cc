## 背景

一覧を最新にする操作が、⟳(search の再実行)と Rescan(reconcile)の 2 つに分かれている。メニューには、
ボタンと同じ操作の項目がある。検索欄にフォーカスがある間は、下部パネルに、キーで実行できないボタンが残る。
History の見出しは、上限で制限した行数を、会話の全体の件数のように表示する。行のスピナーは、50ms ごとに
メインスレッドで表示を更新する。⌄ メニューを開いた後は、他のアプリに切り替えても、ポップオーバーが閉じない。
これらを、DESIGN.md の仕様に合わせて変更する。

## タスク

### T1: Refresh(⟳ と ⌘R)

既存実装: `MainSurfaceModel.swift`(`refreshClicked`、`settleRefreshAtWholeTurn`、`showRescanFeedback`)、
`AppState.swift`(`runReconcile`、`rescanFeedback`)、`ShiibarCcCore` の `MessageLine.swift` と `RescanFeedback.swift`、
`UnifiedListView.swift`(`RefreshButton`)。

- Refresh は、search の再実行と `shiibar-cc reconcile` の両方を開始し、両方の終了を待つ(§4.6)。
  実行中の Refresh の再実行は、何もしない
- 終了後の表示は、§4.6 の表(search と reconcile の結果の組み合わせ)のとおりにする。結果から表示を決める判定は
  Core に実装し、表の全行をテストする
- 一時表示は `Refreshing…` / `✓ Refresh done` / `Refresh failed` だけにする。`Updated · N conversations` と、
  `Rescanning…` / `✓ Rescan done` / `Rescan failed` は廃止する(型と文言と、不要になった状態を削除する)
- ⟳ の回転の規則(真上から開始、最低 1 回転、回転の区切りで停止 — §4.6 / §9)は変更しない。回転を終了できる時点は、
  search と reconcile の両方が終了した時点である
- 起動時・再接続時・定期の reconcile は変更しない(一時表示なし。TCC エラーは警告行)
- ⌘R を、ポップオーバーとウィンドウのキー操作に追加する(§4.5「キー操作」の表。検索欄にフォーカスがある間も、
  どのページでも同じ。日本語入力の変換が未確定の間の規則は、ほかのキーと同じ)。既存のキーの判定(Core)に追加する
- ⟳ のツールチップを `Refresh (⌘R)` にする

### T2: メニュー

既存実装: `MainSurfaceController.swift`(`presentMenu`、`HeaderMenuHandler`)、`AppMenu.swift`(`AppMenuCommands`、`AppMenuModel`)。

- ⌄ メニューから Rescan を削除する。構成は §4.5「⌄ メニュー」のとおり
- アプリメニューから Setup Check…、Rescan(⌘R)、Clear badges を削除する。構成は §4.5 のアプリメニューの構成のとおり
- 削除によって使用しなくなったコード(メニューのための状態の監視など)を削除する。⌄ メニューの Clear badges の
  有効と無効の切り替えは変更しない

### T3: ピンのアイコン

既存実装: `SurfaceStyle.swift`(`SurfaceIcon.pin`、`SurfaceIconView`、`HoverChipButtonStyle`)、`UnifiedListView.swift`(見出し行)。

- アイコンの形を、`docs/window-design.html` の `i-pin`(16 の格子のパス、線の太さ 1.2、角は丸い結合)にする
- OFF: 二次色の輪郭だけ。ホバーと押下の背景は、ほかの見出し行のボタンと同じ
- ON: アイコンはアクセントカラーの塗り。ボタンの背景は、アクセントカラーの 16%(押している間は 24%)。
  背景の大きさと角の半径は、ほかの見出し行のボタンのホバーの背景と同じ
- アイコンの大きさ(文字の大きさへの連動を含む)は、ほかの見出し行のアイコンと同じ規則のままにする

### T4: ポップオーバーを閉じる処理

既存実装: `MainSurfaceController.swift`(ポップオーバーの表示と `performClose`)。

- `NSApplication.didResignActiveNotification` を受信した時点で、ポップオーバーを表示していれば閉じる(§4.5「ポップオーバー」/ §8.58)。
  ウィンドウは閉じない
- 通知の受信はテストできる形にする(通知を送信するオブジェクトを差し替えて、表示中は閉じる処理が呼ばれること、
  表示していない間は呼ばれないことを確認する)。テストで実際のポップオーバーとウィンドウを画面に表示しない

### T5: 下部パネルのボタン

既存実装: `UnifiedListState.swift`(`showsShortcuts: !isSearchFieldFocused` と、下部パネルの表示を決める型)、
`UnifiedListView.swift` と `ConversationPaneView.swift`(下部パネルの描画)。

- 検索欄にフォーカスがある間は、行を選択していても、下部パネルのボタンを表示しない(§4.6「下部パネル」)。
  1 列でも 2 列でも同じ。パネルの高さは変更しない。1 列のキーの案内(`↩ List`)は表示する
- 「記号だけを表示しない」状態は廃止する(表示しているボタンは、常に記号を表示する)。不要になった引数と分岐を削除する
- 表示するかどうかの判定は Core に実装する

### T6: History の見出し

既存実装: `UnifiedListState.swift`(区画の見出しと、上限を超えたときの末尾の行)、`UnifiedListView.swift`(見出しの描画)。

- 上限を超えた会話がある間は、History の見出しの行数の位置に `first 100` を表示する(§4.6「History の区画」。
  数は §9 の上限の定数から作成する)。上限以下の間は、現在と同じ行数である。文字の色と大きさは、行数と同じ
- 見出しの文字列を決める処理は Core に実装する

### T7: 行のスピナー

既存実装: `RowSymbolView.swift`(`TimelineView` による working のスピナー)、`ShiibarCcCore` の `GlyphCycleSpinner.swift`。

- working のスピナーのグリフの切り替えを、Core Animation のアニメーション(レイヤーの内容を、キーフレームで離散的に
  切り替えるアニメーション)で実行する。アニメーションの実行中に、グリフの切り替えのたびにメインスレッドで
  表示を更新する処理(`TimelineView`、タイマー)を使用しない。使用しなくなる定数(`tickIntervalSeconds`)と、
  その定数についてのコメントを削除する
- グリフ(6 種類)、周期(2 秒)、計算式(§9)は変更しない。1 周期の中の切り替えの時刻(計算式の値が変化する時刻)と、
  各区間のグリフの番号を返す処理を Core に実装する。既存の `frameIndex(atReferenceTime:)` と結果が一致することをテストする
  (区間の内側の時刻で比較する)
- 複数の行のスピナーは、同じ時刻に同じグリフを表示する(アニメーションの開始の位相を、共通の時計の時刻から決める。
  後から表示された行も一致する)
- 見た目(グリフの大きさ、位置、色、濃度)は、変更の前と同じにする。次の変化に追従する:
  ライトとダークの切り替え、文字の大きさの変更、ディスプレイの倍率の変化(倍率の違うディスプレイへのウィンドウの移動)
- スピナーを動作させる条件(ポップオーバーまたはウィンドウを表示している間で、行が working)は変更しない。
  動作させない間は、アニメーションを削除する。行のビューがウィンドウに再度追加された場合と、行の位置が変化した場合も、
  動作が継続する
- idle と waiting の記号、赤バッジは変更しない

  (検索欄にフォーカスがある間 / 一覧にフォーカスがある間 / 詳細ページ / 日本語入力の変換が未確定の間)、
  下部パネルのボタンを表示する条件(選択なし / 選択あり × フォーカスの位置 × 1 列と 2 列)、
  History の見出し(上限未満 / 上限ちょうど / 上限を超える / 検索中)、スピナーの切り替えの時刻と番号
- App: Refresh が search と reconcile の両方を開始すること、片方だけが終了した時点では実行中のままであること、
  実行中の再実行で何も開始しないこと、⌘R と ⟳ が同じ処理を実行すること、
  非アクティブの通知でポップオーバーを閉じる処理(T4)。外部のコマンドの実行は、既存の差し替えの仕組みを使用する
  (テストは実際の `shiibar-cc` を実行しない)
- 廃止する表示と項目のテストは、新しい仕様のテストに置き換える(仕様に残る規則のテストは弱めない)

- docs/ 以外に日本語を記述しない(コメントで仕様を参照する場合は、英語に翻訳して節番号を記載する)。
  コメントとテストの名前には、処理が必要な条件と理由を記述し、変更の経緯を記述しない
